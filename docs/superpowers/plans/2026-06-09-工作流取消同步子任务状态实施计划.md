# 工作流取消同步子任务状态 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 取消 graph workflow 时，同步停止运行中的 implementation child task 和对应 `workflowPlan.tasks[*]` 状态，避免并行任务表在工作流取消后仍显示子任务 running。

**Architecture:** `cancelGraphWorkflow()` 已取消 active agent runs、running steps 和顶层 run/state。本切片在同一路径中收集被取消 running step 关联的 child task id：child task 从 `in_progress` 标记为 `failed`，对应 workflowPlan task 从 `running` 标记为 `blocked`。pending sibling 不改动。

**Tech Stack:** Node.js、TypeScript、SQLite/better-sqlite3、node:test。

新增 helper：

```ts
function markWorkflowPlanTasksBlockedByChildIds(
  state: AgentWorkflowState,
  childTaskIds: Set<string>,
): AgentWorkflowState['workflowPlan'] {
  if (!state.workflowPlan || childTaskIds.size === 0) return state.workflowPlan ?? null;
  const planIndexes = new Set(Object.entries(state.childTaskPlanIndexes ?? {})
    .filter(([childTaskId]) => childTaskIds.has(childTaskId))
    .map(([, planIndex]) => planIndex));
  if (planIndexes.size === 0) return state.workflowPlan;
  return {
    ...state.workflowPlan,
    tasks: state.workflowPlan.tasks.map((task, index) =>
      planIndexes.has(index) ? { ...task, status: 'blocked' } : task
    ),
  };
}
```

写入 cancelled graph state 时使用该 helper。

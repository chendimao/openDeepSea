# 工作流重试同步计划任务状态 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 graph workflow 重试失败或中断的 implementation 子任务时，同步复位 `workflowPlan.tasks[*]` 状态，避免并行调度 selector 因计划任务仍是 `failed/blocked` 而跳过已重置为 `todo` 的 child task。

**Architecture:** 在 `retryGraphWorkflow()` 中收集被重置的 child task id，基于 `state.childTaskPlanIndexes` 找到对应 workflow plan task，并在写入 retry graph state 前把这些任务恢复为 `pending`、`progress: 0`。该修复只处理 retry 目标 child，不影响已完成 sibling。

**Tech Stack:** Node.js、TypeScript、SQLite/better-sqlite3、node:test。

- [x] **Step 2: 新增 workflowPlan reset helper**

新增 helper：

```ts
function resetWorkflowPlanTasksForRetry(
  state: AgentWorkflowState,
  childTaskIds: Set<string>,
): AgentWorkflowState['workflowPlan'] {
  if (!state.workflowPlan || childTaskIds.size === 0) return state.workflowPlan ?? null;
  return {
    ...state.workflowPlan,
    tasks: state.workflowPlan.tasks.map((task, index) => {
      const shouldReset = Object.entries(state.childTaskPlanIndexes ?? {})
        .some(([childTaskId, planIndex]) => childTaskIds.has(childTaskId) && planIndex === index);
      if (!shouldReset) return task;
      return {
        ...task,
        status: 'pending',
        progress: 0,
      };
    }),
  };
}
```

如需优化，可先构造 index set，避免在 map 中重复遍历。

- [x] **Step 3: 将 helper 应用到 retryState**

构造 `retryState` 时使用：

```ts

```

注意 `resetChildTaskIds` 必须在构造 `retryState` 前完成。

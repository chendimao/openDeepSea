# 轻量实现任务自动工作流实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 将低风险实现类 Session 消息自动交给 workflow graph 和专项执行智能体，不再由 session planner 直接修改代码。

**架构：** 保留现有风险门禁作为“是否等待用户确认”的唯一判断；新增独立的实现任务路由判断。中高风险任务继续等待确认后启动 workflow，低风险的前端、后端、全栈、修复、测试和配置实现任务直接创建 workflow bridge task 并自动执行；分析、问答、头脑风暴继续由 planner 处理。

**技术栈：** TypeScript、Node.js、SQLite、现有 workflow graph、Node test runner。

---

assert.equal(sessionRunRepo.listBySession(session.id).length, 0);
assert.deepEqual(

    'code_review:reviewer',

```

同时断言源消息 metadata 包含 `session_execution.executionPath = "workflow_graph"` 及 workflow task/run id。

```

预期：失败，当前实现创建了 planner session run，没有 workflow task/run。

### Task 2：拆分审批判断与执行路由

**文件：**
- 修改：`packages/backend/src/session-message-dispatch.ts`

- [ ] **Step 1：补充实现意图信号**

在开发信号和前端任务信号中覆盖“去掉、移除、隐藏、状态栏、底部栏”，使自然语言轻量 UI 任务稳定识别为 `frontend_change`。

- [ ] **Step 2：新增低风险自动 workflow 路由**

在风险门禁之后、`startSessionPlannerRun` 之前判断：

```ts
if (shouldStartAutomaticWorkflow(riskGate.assessment)) {
  startAutomaticSessionWorkflow(...);
  return message;
}
```

只对 `frontend_change`、`backend_change`、`fullstack_change`、`bug_fix`、`test_only`、`ops_or_config` 生效。

- [ ] **Step 3：记录自动执行 metadata**

在源消息 metadata 中记录：

```ts
session_execution: {
  executionPath: 'workflow_graph',
  trigger: 'low_risk_auto',
  workflowRoomId,
  workflowTaskId,
  workflowRunId,
}
```

不得伪造 `session_approval.status = "approved"`。

- [ ] **Step 4：复用现有任务描述和子任务拆解**

将 workflow task 描述构建逻辑调整为同时接受审批执行上下文和低风险自动执行上下文，保持前端执行、review、acceptance 阶段不变。

# 工作流并行调度高风险写入串行保护 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 防止 graph workflow 把修改根配置、lockfile、迁移、CI、shared contract/shared types 的 implementation 子任务与其他子任务并行启动。

**Architecture:** 在 execute 调度选择阶段增加 `scopeWritesRequireSerial()`。并行 batch 遇到 ready 的高风险写入任务直接放弃批次，让现有单 child fallback 串行启动；单 child fallback 若检测到已有 active writes，则跳过高风险任务，同时 active high-risk write 会阻止其他 sibling 启动。

**Tech Stack:** Node.js、TypeScript、SQLite/better-sqlite3、node:test。

## Task 2: 实现高风险写入串行保护

**Files:**
- Modify: `packages/backend/src/workflows/graph/nodes.ts`

- [x] **Step 1: 新增高风险 scope helper**

新增：

```ts
function scopeWritesRequireSerial(writes: string[], projectPath: string): boolean
```

规则：

- `package.json`
- `package-lock.json`
- `pnpm-lock.yaml`
- `yarn.lock`
- `npm-shrinkwrap.json`
- `.github/`
- `migrations/` 或包含 `/migrations/`
- `schema/` 或包含 `/schema/`
- `shared/` 或包含 `/shared/`
- `contracts/` 或包含 `/contracts/`
- `types/` 或包含 `/types/`
- `tsconfig.json`、`vite.config.*`、`eslint.config.*`

- [x] **Step 2: batch selector 遇到高风险任务放弃批次**

在 `selectParallelImplementationBatch()` 中解析 writes 后：

```ts
if (scopeWritesRequireSerial(writes, input.projectPath)) return [];
```

同时如果 active writes 中有高风险写入，也返回空 batch。

- [x] **Step 3: 单 child fallback 保护 active 并发**

在 `selectNextImplementationChild()` 中：

- 如果 active writes 里有高风险写入，返回 `undefined`。
- 如果当前 child writes 高风险且 active writes 非空，跳过该 child。

Run:

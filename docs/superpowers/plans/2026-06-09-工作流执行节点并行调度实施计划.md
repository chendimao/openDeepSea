# 工作流执行节点并行调度 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Superpowers graph workflow 的 `execute` 节点在同一轮调度中并发启动多个 ready、无写范围冲突、执行智能体不同的 implementation 子任务。

**Architecture:** 保留现有 `executeNode` 单子任务路径作为兼容 fallback；新增并行批次选择 helper，先按 `workflowPlan.tasks[*].depends_on` 判断 DAG ready，再用 `scopeWrite` 和 assigned agent 去除冲突。批次内任务先整批解析 executor，确保没有缺失 runtime 后再串行创建 step/status/prompt 事实，用 `Promise.all` 并发调用 `runAcpAgent`，最后按原顺序汇总 artifact、step、task status 和 workflowPlan 状态。

**Tech Stack:** Node.js、TypeScript、SQLite/better-sqlite3、node:test。

function createAcpExecutor(roomId: string, agentId: string, writableDirs: string[]): RoomAgent {
  const agent = roomAgentRepo.add({
    room_id: roomId,
    agent_id: `${agentId}-${Date.now()}-${Math.random()}`,
    agent_name: agentId,
  });
  const withRole = roomAgentRepo.setWorkflowRole(agent.id, 'executor') ?? agent;
  const withAcp = roomAgentRepo.setAcp(withRole.id, {
    acp_enabled: true,
    acp_backend: 'codex',
    acp_session_id: null,
    acp_session_label: null,
    acp_permission_mode: 'workspace-write',
  }) ?? withRole;
  return roomAgentRepo.setCapabilitiesAndRuntime(withAcp.id, {
    capabilities: withAcp.capabilities,
    default_runtime: withAcp.default_runtime,
    tool_policy: { allowed: ['read_files', 'write_files'] },
    workspace_policy: { read: ['.'], write: writableDirs },
  }) ?? withAcp;
}

async function waitForExecuteTest(predicate: () => boolean, attempts = 20): Promise<void> {
  for (let index = 0; index < attempts; index += 1) {
    if (predicate()) return;
    await new Promise((resolve) => setTimeout(resolve, 10));
  }
  assert.equal(predicate(), true);
}

```ts
function selectParallelImplementationBatch(input: {
  state: AgentWorkflowState;
  childTasks: Task[];
  childTaskPlanIndexes: Record<string, number>;
}): Task[] {
  const workflowPlan = input.state.workflowPlan;
  if (!workflowPlan) return [];
  const planTaskById = new Map(workflowPlan.tasks.map((task) => [task.id, task]));
  const selected: Task[] = [];
  const selectedAgentIds = new Set<string>();
  const selectedWrites: string[][] = [];
  for (const child of input.childTasks) {
    if (child.status !== 'todo' && child.status !== 'in_progress') continue;
    const planIndex = input.childTaskPlanIndexes[child.id] ?? -1;
    const planTask = workflowPlan.tasks[planIndex];
    const parsedPlanTask = input.state.plan?.tasks[planIndex];
    if (!planTask || planTask.role !== 'executor' || planTask.mode !== 'parallel') continue;
    const dependenciesReady = planTask.depends_on.every((dependencyId) => {
      const dependency = planTaskById.get(dependencyId);
      return dependency?.status === 'completed' || dependency?.status === 'skipped';
    });
    if (!dependenciesReady) continue;
    const agentId = child.assigned_agent_id ?? planTask.agent_id;
    if (!agentId || selectedAgentIds.has(agentId)) continue;
    const writes = parsedPlanTask?.scopeWrite ?? [];
    if (selectedWrites.some((existing) => scopeWritesConflict(existing, writes))) continue;
    selected.push(child);
    selectedAgentIds.add(agentId);
    selectedWrites.push(writes);
  }
  return selected.length > 1 ? selected : [];
}
```

并新增 `scopeWritesConflict()`、`normalizeScopePath()`、`isBroadScopePath()`，用路径前缀判断 `.`、项目根、父目录与子目录冲突；空 `scopeWrite` 不与其他任务冲突。

- [x] **Step 2: 接入 executeNode**

在 `executeNode` 计算 `executionCandidates` 后：

1. 先检查 `tools.listActiveAgentRunsByWorkflow(context.run.id)` 是否有 implementation active run；有则保留原有单 run wait 逻辑。
2. 计算 `childTaskPlanIndexes`。
3. 调用 `selectParallelImplementationBatch()`。
4. 当 batch 长度大于 1 时，走 `runParallelImplementationChildren()`；否则保留现有单 child 逻辑。

- [x] **Step 3: 实现 runParallelImplementationChildren**

`runParallelImplementationChildren()` 只覆盖 batch 路径：

1. 对每个 child 解析 plan index、scope、executor。
2. 若某个 executor 缺失，返回 blocked 状态并把对应 workflowPlan task 标为 blocked。
3. 串行创建 step、更新 child 为 `in_progress`、广播 step/task、记录 workflow event。
4. 用 `Promise.all` 并发调用 `tools.runAcpAgent()`。
5. 成功结果创建 `implementation_summary` artifact、更新 step completed、创建 handoff context、把 child status 改为 `review`、workflowPlan task 标为 `completed`。
6. 任一失败结果把对应 step/child/run/state 标为 blocked 或 cancelled；已成功结果保留 completed。

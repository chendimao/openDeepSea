# 状态栏网络延迟 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让会话页底部状态栏的“网络延迟”从固定 `--` 变为基于当前浏览器 WebSocket 连接实时计算的 RTT 毫秒值。

**Architecture:** 复用现有 `/ws` 单连接，不新增 HTTP API 或数据库字段。前端 `SessionSocket` 定时发送应用层 `connection.ping`，服务端在 `session-socket-controller` 中验证并 echo `connection.pong`；前端用 `Date.now() - sentAt` 计算 RTT，并通过 socket listener 事件把值合并进当前 `SessionWorkspacePayload.bottomStatus.networkLatencyMs`。

**Tech Stack:** TypeScript, React 18, Vite, Node.js, Express, `ws`, `zod`, Node test runner, existing `sessionSocket` and `SessionWorkspacePage` state model.

---

## Scope

### In Scope

- 扩展前后端 WebSocket 类型：
  - 客户端事件：`connection.ping`
  - 服务端事件：`connection.pong`
- 服务端对 ping 做 schema 校验并原样回传 `sentAt`。
- 前端在存在订阅或 pending event 时启动轻量 RTT 采样。
- 前端收到 pong 后计算 `networkLatencyMs`，并只更新当前会话 payload 的 `bottomStatus.networkLatencyMs`。
- 保留后端 `buildSessionBottomStatus()` 的 `networkLatencyMs: null` 作为 snapshot 默认值，避免后端 snapshot 伪造浏览器网络延迟。
- 增加定向测试与构建验证。

### Out of Scope

- 不修改数据库 schema。
- 不新增 REST API。
- 不把网络延迟持久化到会话记录。
- 不改底部状态栏布局、颜色或文案。
- 不实现浏览器协议层 WebSocket ping；浏览器 API 不暴露协议层 ping/pong。

- 后端底部状态派生函数目前固定返回 `networkLatencyMs: null`：`packages/backend/src/session-workspace-view-model.ts:76-97`。

```ts
export function computeConnectionLatencyMs(sentAt: number, receivedAt: number): number | null {
  if (!Number.isFinite(sentAt) || !Number.isFinite(receivedAt)) return null;
  return Math.max(0, Math.round(receivedAt - sentAt));
}
```

```ts
  private startLatencyPings(ws: WebSocket): void {
    this.stopLatencyPings();
    this.sendLatencyPing(ws);
    this.latencyPingTimer = setInterval(() => this.sendLatencyPing(ws), CONNECTION_LATENCY_PING_INTERVAL_MS);
  }

  private stopLatencyPings(): void {
    if (this.latencyPingTimer) clearInterval(this.latencyPingTimer);
    this.latencyPingTimer = null;
  }

  private sendLatencyPing(ws: WebSocket): void {
    if (this.ws !== ws || ws.readyState !== WebSocket.OPEN) return;
    ws.send(JSON.stringify({ type: 'connection.ping', sentAt: Date.now() }));
  }
```

## Risks

- **Snapshot overwrite risk:** Task 3 明确保留前端 RTT，避免后端 `networkLatencyMs: null` snapshot 覆盖浏览器刚计算出的值。
- **Timer lifecycle risk:** ping timer 必须在 socket close 和 destroy 时清理，避免多 timer 并发。
- **Protocol confusion risk:** `connection.latency` 是前端内部事件，不应发送到服务端，也不应加入后端 union。
- **Dirty worktree risk:** 当前仓库已有未提交改动与未跟踪文件，执行者提交时必须只 add 本计划列出的文件。

## Acceptance Criteria

- 会话页底部状态栏在 WebSocket 连接稳定后显示类似 `37ms` 的网络延迟值。
- WebSocket 断开后不会继续运行旧 ping timer。
- 服务端收到 `connection.ping` 后返回 `connection.pong`，且保留原始 `sentAt`。
- 前端只用当前浏览器收到 pong 的时间计算 RTT，不使用后端 run 耗时或 fake 固定值。

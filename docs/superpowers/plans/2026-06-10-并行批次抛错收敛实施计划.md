# 并行批次抛错收敛 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** parallel implementation batch 中单个 agent runtime 直接抛错时，execute node 仍应收敛所有已启动子任务状态，而不是让 `Promise.all` 提前 reject。

**Architecture:** 将 parallel batch 的 `Promise.all` 结果包装为“成功 runResult 或抛错 error”的结构，等待所有 prepared 子任务 settle。循环处理时复用已有 completed/failed 状态更新逻辑；对 thrown error 创建 failed step、failed child、blocked run 和 failed workflowPlan task。

**Tech Stack:** Node.js test runner、TypeScript、graph workflow execute node。

- [x] **Step 3: Write minimal implementation**

在 `runParallelImplementationBatch()` 中把 `Promise.all` 包装为：

```ts
const results = await Promise.all(prepared.map(async (item) => {
  try {
    return { item, runResult: await input.tools.runAcpAgent(...), runError: null };
  } catch (err) {
    return { item, runResult: null, runError: err instanceof Error ? err : new Error(String(err)) };
  }
}));
```

循环中先处理 `runError`：

```ts
if (runError) {
  // failed step, failed child, blocked run, failed workflowPlan task, failedState
  continue;
}
```

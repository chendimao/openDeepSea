# AI 模型配置中心 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在系统设置中新增 Provider 配置中心，支持只读同步 Codex / Claude Code / OpenCode 本机全局配置、托管 provider profile，并让 ACP 运行时优先使用托管 profile。

**Architecture:** 后端新增 provider-configs 独立模块，负责 SQLite 持久化、配置目录解析、同步和 runtime config 解析；现有 settings 路由只挂载新 router，不把 provider profile 混入现有 `ai_configs`。前端在 `SettingsDialogs.tsx` 的 `model` 分类中加入 provider 配置中心，保留现有 planner OpenAI-compatible 配置区并新增同步策略、provider 卡片、profile 编辑和运行摘要。

**Tech Stack:** Node.js 20、Express、better-sqlite3、TypeScript、React 18、TanStack Query、Tailwind utility classes、Node test runner、Vite build。

## 并行策略

本任务包含共享 DB schema、共享类型、settings API 和同一前端设置文件，写入阶段不适合让多个子代理并行修改同一 contract。当前子代理工具也不支持仓库规则要求的 `model` 与 `reasoning_effort` 显式参数，因此实现由主会话串行推进；代码审查与浏览器验证在最终阶段执行。

- [x] **Step 3: 实现 DB schema**

在 `packages/backend/src/db.ts` 的初始 schema 中加入：

```sql
CREATE TABLE IF NOT EXISTS provider_config_sources (
  provider TEXT PRIMARY KEY CHECK (provider IN ('claudecode', 'opencode', 'codex')),
  config_dir TEXT,
  use_default_config_dir INTEGER NOT NULL DEFAULT 1 CHECK (use_default_config_dir IN (0, 1)),
  auto_sync_enabled INTEGER NOT NULL DEFAULT 1 CHECK (auto_sync_enabled IN (0, 1)),
  last_sync_at INTEGER,
  last_sync_status TEXT NOT NULL DEFAULT 'idle' CHECK (last_sync_status IN ('idle', 'success', 'failed')),
  last_sync_error TEXT,
  updated_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS provider_config_snapshots (
  provider TEXT PRIMARY KEY CHECK (provider IN ('claudecode', 'opencode', 'codex')),
  config_dir TEXT NOT NULL,
  config_file TEXT,
  detected_model TEXT,
  detected_base_url TEXT,
  api_key_set INTEGER NOT NULL DEFAULT 0 CHECK (api_key_set IN (0, 1)),
  api_key_preview TEXT,
  reasoning_effort TEXT,
  raw_summary_json TEXT NOT NULL DEFAULT '{}',
  synced_at INTEGER NOT NULL
);

CREATE TABLE IF NOT EXISTS provider_profiles (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  provider TEXT NOT NULL CHECK (provider IN ('claudecode', 'opencode', 'codex')),
  model TEXT,
  base_url TEXT,
  api_key TEXT,
  reasoning_effort TEXT,
  run_overrides_enabled INTEGER NOT NULL DEFAULT 1 CHECK (run_overrides_enabled IN (0, 1)),
  is_active INTEGER NOT NULL DEFAULT 0 CHECK (is_active IN (0, 1)),
  created_from_snapshot_at INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_provider_profiles_active
  ON provider_profiles(provider)
  WHERE is_active = 1;
```

- [x] **Step 4: 实现类型与 parser**

`types.ts` 定义 `ACP_PROVIDERS`、默认目录、safe 类型、runtime 类型。`parser.ts` 导出：

```ts
export async function discoverProviderConfig(input: {
  provider: AcpBackend;
  configDir: string;
```

解析规则：

- Codex 读取 `config.toml`，用正则解析 top-level `model_provider`、`model`、`model_reasoning_effort`，再读取匹配 `[model_providers.<name>]` 中的 `base_url` 和常见 key 字段。
- Claude Code 读取 `settings.json`，优先解析 `env.ANTHROPIC_MODEL`、`env.ANTHROPIC_BASE_URL`、`env.ANTHROPIC_API_KEY`，兼容顶层同名字段。
- OpenCode 读取 `opencode.json`，解析顶层 `model`，再从 `provider[providerName]` 读取 `baseURL`、`apiKey`、reasoning options。

- [x] **Step 5: 实现 service**

`service.ts` 导出 `providerConfigService`，包含：

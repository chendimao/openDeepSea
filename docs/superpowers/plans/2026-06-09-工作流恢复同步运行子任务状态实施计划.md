# 工作流恢复同步运行子任务状态 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 后端重启恢复 graph workflow 时，同步停止正在执行的子任务，并把对应 `workflowPlan.tasks` 标记为 blocked。

**Architecture:** 在 `recoverGraphWorkflow()` 解析当前 graph state 后，根据 running step 的 `task_id` 是否属于 `childTaskIds` 收集受影响子任务。恢复流程继续保持父 workflow blocked、step/agent run interrupted，同时复用现有 `markWorkflowPlanTasksBlockedByChildIds()` 同步计划状态。

**Tech Stack:** Node.js test runner、TypeScript、SQLite repositories、graph workflow runtime。

- [x] **Step 3: Write minimal implementation**

在 `recoverGraphWorkflow()` 的 running step 循环中：

```ts
let parsedState: AgentWorkflowState | null = null;
try {
  parsedState = tools.parseGraphState(run.graph_state);
} catch (err) {
  console.warn(...);
}
const interruptedChildTaskIds = new Set<string>();
const childTaskIdSet = new Set(parsedState?.childTaskIds ?? []);
if (step.task_id && childTaskIdSet.has(step.task_id)) interruptedChildTaskIds.add(step.task_id);
for (const childTaskId of interruptedChildTaskIds) {
  const child = taskRepo.get(childTaskId);
  if (child?.status !== 'in_progress') continue;
  const failedChild = taskRepo.updateStatus(child.id, 'failed');
  if (failedChild) tools.broadcastTaskUpdated(failedChild);
}
```

写入 graph state 时把 `workflowPlan` 更新为：

```ts
workflowPlan: markWorkflowPlanTasksBlockedByChildIds(parsedState, interruptedChildTaskIds)
```

# 工作流阻塞同步运行子任务状态 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** graph workflow 在共享异常阻塞路径中停止 running implementation step 时，同步更新对应子任务与 `workflowPlan.tasks` 状态。

**Architecture:** `blockGraphWorkflowRun()` 是 `continueGraphWorkflow()` 异常、后台异常和 Superpowers gate 复用的共享 block helper。扩展该 helper：遍历 running steps 时收集属于 `state.childTaskIds` 的 child task，失败对应 `in_progress` 子任务，并用已有 child-task 到 plan-index 映射更新 `workflowPlan`。

**Tech Stack:** Node.js test runner、TypeScript、SQLite repositories、graph workflow runtime。

- [x] **Step 3: Write minimal implementation**

在 `blockGraphWorkflowRun()` 中：

```ts
const failedChildTaskIds = new Set<string>();
const childTaskIdSet = new Set(state?.childTaskIds ?? []);
for (const step of workflowRepo.listSteps(runId).filter((item) => item.status === 'running')) {
  if (step.task_id && childTaskIdSet.has(step.task_id)) failedChildTaskIds.add(step.task_id);
  workflowRepo.updateStep(step.id, { status: 'failed', error });
}
for (const childTaskId of failedChildTaskIds) {
  const child = taskRepo.get(childTaskId);
  if (child?.status !== 'in_progress') continue;
  taskRepo.updateStatus(child.id, 'failed');
}
```

返回 state 时：

```ts
workflowPlan: markWorkflowPlanTasksBlockedByChildIds(state, failedChildTaskIds)
```

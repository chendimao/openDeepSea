# 会话变更按当前会话统计修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 Session Workspace 右侧栏「本次会话变更」错误混入全工作区 Git 变更的问题，使其只展示当前 session 的 ACP/evidence 文件变更。

**Architecture:** 后端 `buildSessionInspectorSnapshot()` 作为右侧 Inspector snapshot 的唯一派生入口，但 `diffRows` 只来自当前 session 的 `buildSessionDiffRowsFromAcp(evidence, agentEvents)`。全工作区 live git 变更继续保留在 `buildSessionDiffRows(workspacePath)` 工具函数和底部 Git 状态能力中，不再合并进右侧「本次会话变更」。前端保持现有 `session_inspector:snapshot` 替换 `diffRows` 的刷新路径，并用测试锁定旧 diffRows 可被空 snapshot 清空。

**Tech Stack:** TypeScript, Node.js `node:test`, React 18, Vite, WebSocket session events, SQLite repo tests.

## Current Diagnosis

根因在后端：`buildSessionInspectorSnapshot()` 当前将两类数据合并：

```ts
diffRows: mergeSessionDiffRows(
  buildSessionDiffRowsFromAcp(evidence, agentEvents),
  buildSessionDiffRows(workspacePath),
),
```

`buildSessionDiffRows(workspacePath)` 读取的是 live git 工作区状态，和当前 session 无关。同一项目下所有 session 使用同一工作区路径时，会看到同一批未提交文件；新 session 没有产生文件变更，也会显示已有 Git 变更。

正确口径是：右侧「本次会话变更」只来自当前 session 的 evidence 和 agent events；live git 工作区状态属于底部状态栏或独立 Git 能力。

  sessionId: string,

  agentEvents: SessionAgentEvent[],

- [ ] **Step 2: 删除无引用的 `mergeSessionDiffRows()`**

在 `packages/backend/src/session-workspace-view-model.ts` 删除以下私有函数：

```ts
function mergeSessionDiffRows(
  eventRows: SessionDiffRow[],
  gitRows: SessionDiffRow[],
): SessionDiffRow[] {
  const rows = new Map<string, SessionDiffRow>();
  for (const row of eventRows) rows.set(row.path, row);
  for (const row of gitRows) {
    const existing = rows.get(row.path);
    rows.set(row.path, {
      path: row.path,
      status: row.status,
      additions: row.additions ?? existing?.additions ?? null,
      deletions: row.deletions ?? existing?.deletions ?? null,
      summary: row.summary ?? existing?.summary ?? null,
    });
  }
  return [...rows.values()];
}
```

不要删除导出的 `buildSessionDiffRows(workspacePath)`，它仍用于 git diff 独立能力和测试。

## Risks

- 旧 session 如果没有结构化 ACP/evidence 文件变更事件，右侧栏会显示空，这是符合“只统计当前会话更改的文件”的取舍。
- `buildSessionDiffRows(workspacePath)` 仍保留，执行者不能误删它，否则会影响独立 git diff 能力。
- 当前工作区已有多处未提交改动，执行者必须只 stage 本任务相关文件，不能回滚或混入无关文件。
- 如果测试环境没有 `git` 命令，Task 1/2 后端测试会失败；需要在验证结果中明确说明环境缺失，而不是声称通过。

## Acceptance Criteria

- 新 session 没有 ACP/evidence 文件变更时，右侧栏「本次会话变更」显示空态。
- 同一项目内其他 session 的 live git 未提交文件不会显示到当前 session 的右侧栏。
- 当前 session 产生 `file_diff` 或 `apply_patch` 结构化事件时，右侧栏显示对应文件。
- `session_inspector:snapshot.diffRows = []` 能清空前端旧的 `diffRows`。
- 定向测试通过：后端 view model、前端 workspace events、前端 session workspace page。
- `npm run build` 通过。

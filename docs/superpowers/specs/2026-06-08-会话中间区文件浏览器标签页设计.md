# 会话中间区文件浏览器标签页设计

## 背景

当前会话页面中间区域直接展示对话记录，左侧项目/会话树、右侧 Inspector 与底部状态栏已经形成稳定三栏工作台。新的目标是在不改动左右栏和底部状态栏的前提下，把中间消息模块升级为类似 VS Code 的标签页工作区，并在文件浏览器里支持项目目录、代码/文本预览、图片预览与后续文档预览扩展。

本设计基于以下已确认依赖能力：

- `flexlayout-react@0.9.1`：多标签 docking layout 管理器，用于外层固定 tab 与内层文件 tab。
- `react-complex-tree@2.6.1`：可访问文件树组件，支持展开、选择、键盘导航与自定义渲染。
- `monaco-editor@0.55.1`：浏览器代码编辑器，用于代码/文本只读预览。
- `@monaco-editor/react@4.7.0`：React 封装层，底层仍使用 `monaco-editor`，用于降低 React/Vite 集成成本。

## 目标

1. 保持会话页现有左侧项目/会话树、右侧 Inspector、底部状态栏不变。
2. 将中间区域改为外层 FlexLayout，两项固定 tab：
   - `对话记录`
   - `文件浏览器`
3. 在 `文件浏览器` tab 内提供左侧常驻项目目录树和右侧文件 tabs。
4. 文件 tabs 支持同路径复用、关闭、排序，不支持分屏。
5. 文件预览第一版只读，不支持编辑、保存、脏状态和冲突处理。
6. 代码/文本使用 Monaco 预览；图片使用图片 viewer；PDF、Office 等文档先显示不支持预览，同时预留 viewer 扩展点。

## 非目标

- 不做文件编辑和保存。
- 不做文件 tab 分屏、拖出、浮窗或多 tabset。
- 不做 PDF、Office 等文档预览实现。
- 不改造左侧项目/会话树、右侧 Inspector、底部状态栏。
- 不引入 VS Code workbench、LSP、诊断、Git 面板、终端或插件系统。

## 信息架构

会话页仍保持现有三栏骨架：

```text
[项目/会话树] [中间工作区] [Inspector]
              [底部状态栏跨全局]
```

中间工作区改为两层：

```text
SessionCenterWorkspace
├─ 外层 FlexLayout
│  ├─ 对话记录 tab（固定，不可关闭）
│  └─ 文件浏览器 tab（固定，不可关闭）
└─ 文件浏览器 tab 内容
   ├─ WorkspaceFileTree（react-complex-tree）
   └─ WorkspaceFileTabs（内层 FlexLayout 单 tabset）
      ├─ 文件 tab A
      ├─ 文件 tab B
      └─ 文件 tab N
```

外层 tab 只负责在“对话记录”和“文件浏览器”之间切换。文件 tab 不进入外层 tab strip，避免对话工作流和文件工作流混在同一层。

## 组件边界

### `SessionShellView`

保留现有三栏布局和现有 props。中间区域从直接渲染 `TranscriptCanvas` 调整为渲染 `SessionCenterWorkspace`。

### `SessionCenterWorkspace`

职责：

- 创建外层 `flexlayout-react` model。
- 固定两个 tab：`transcript` 与 `file-browser`。
- 将现有对话流、滚动跟随逻辑、composer 继续封装在 `TranscriptWorkspaceTab` 中。
- 将文件相关能力交给 `FileBrowserWorkspace`。

规则：

- `对话记录` 永远第一个。
- `文件浏览器` 永远第二个。
- 两个 tab 都不可关闭。
- 外层不允许拖出、分屏或生成新 tabset。

### `TranscriptWorkspaceTab`

承载现有 `TranscriptCanvas` 行为。保留：

- 消息 timeline。
- agent run 展示。
- 自动跟随滚动。
- `DeepseaComposer` 输入区。
- 当前对话相关的 query 和 display mode 状态。

### `FileBrowserWorkspace`

职责：

- 维护文件树展开状态、选中路径、搜索输入。
- 管理打开的文件 tabs。
- 将目录树和文件 tabs 左右布局固定在 `文件浏览器` tab 内。

布局：

```text
[WorkspaceFileTree] [WorkspaceFileTabs]
```

### `WorkspaceFileTree`

使用 `react-complex-tree` 渲染项目目录。

行为：

- 根目录首次进入 `文件浏览器` tab 时加载。
- 展开目录时按路径懒加载子节点。
- 点击目录仅展开或收起。
- 点击文件打开或聚焦对应文件 tab。
- 搜索优先复用已有 workspace search 接口。

### `WorkspaceFileTabs`

建议使用第二个 `flexlayout-react` model，但只配置单 tabset。

行为：

- 文件 tab 从内层 tabset 管理。
- 同一路径只打开一个 tab；重复点击聚焦已有 tab。
- 文件 tab 可关闭。
- 文件 tab 可在内层 tabset 内排序。
- 禁止拖出、分屏、创建新 tabset。
- 关闭最后一个文件 tab 时显示空状态。

### `FileViewer`

按文件类型分发 viewer：

```text
FileViewer
├─ MonacoTextViewer
├─ ImageViewer
└─ UnsupportedViewer
```

分发依据优先级：

1. 后端返回的 `mimeType`。
2. 后端返回的 `language`。
3. 文件扩展名兜底。

### `MonacoTextViewer`

职责：

- 显示代码/文本文件。
- 全部只读。
- 按文件路径缓存 Monaco model。
- 关闭 tab 时释放未被其他 tab 使用的 model。

适用范围：

- TypeScript、JavaScript、JSON、Markdown、CSS、HTML、Shell、Python、Go、Rust 等文本类文件。
- 普通 `.txt`、`.md` 等文本文件。

### `ImageViewer`

职责：

- 使用 `<img>` 预览图片。
- 展示文件路径、类型、大小等信息。
- 支持加载失败和重试状态。

图片读取需要新增安全 blob 接口，详见后端接口设计。

### `UnsupportedViewer`

职责：

- 展示不支持预览的文件信息。
- 用统一文案说明当前版本只支持代码/文本和图片预览。
- 为后续 `PdfViewer`、`OfficeViewer` 留出注册入口。

## 状态模型

前端维护的核心状态：

```ts
type OpenWorkspaceFileTab = {
  id: string;
  path: string;
  name: string;
  mimeType: string | null;
  language: string | null;
  viewer: 'text' | 'image' | 'unsupported';
};
```

建议派生规则：

- `id` 使用稳定前缀，例如 `file:${path}`。
- `path` 是后端规范化后的 workspace 相对路径。
- `viewer` 由 `resolveWorkspaceFileViewer` 统一计算。

状态操作：

- `openFile(path)`：不存在则新增 tab，存在则聚焦。
- `closeFile(path)`：关闭 tab，释放 viewer 资源。
- `reorderFiles(ids)`：只重排文件 tabs。
- `focusFile(path)`：聚焦已有 tab。

## 数据流

### 打开文件浏览器

1. 用户点击外层 `文件浏览器` tab。
2. 前端请求根目录：
   `GET /api/projects/:projectId/workspace/tree?path=`
3. 文件树渲染根节点。
4. 右侧文件 tab 区显示空状态：“从左侧目录选择文件”。

### 展开目录

1. 用户展开某个目录。
2. 前端请求：
   `GET /api/projects/:projectId/workspace/tree?path=<dir>`
3. 将子节点写入 tree data provider。
4. 请求失败时在对应目录或树区域显示错误和重试。

### 打开文本/代码文件

1. 用户点击文件树中的文本/代码文件。
2. 若同路径 tab 已存在，直接聚焦。
3. 若不存在，新增文件 tab。
4. 前端请求：
   `GET /api/projects/:projectId/workspace/file?path=<file>`
5. `MonacoTextViewer` 使用返回的 `content`、`language`、`mimeType` 渲染只读内容。

### 打开图片文件

1. 用户点击图片文件。
2. 前端新增或聚焦图片 tab。
3. `ImageViewer` 使用新增 blob 接口读取图片：
   `GET /api/projects/:projectId/workspace/blob?path=<file>`
4. 返回成功后用浏览器图片能力展示。
5. 返回失败时展示错误和重试。

### 打开不支持文件

1. 用户点击 PDF、Office 或其他二进制文件。
2. 前端打开文件 tab。
3. `UnsupportedViewer` 展示文件信息和不支持预览提示。

## 后端接口

### 复用已有接口

已有接口：

- `GET /api/projects/:projectId/workspace/tree?path=...`
- `GET /api/projects/:projectId/workspace/file?path=...`
- `GET /api/projects/:projectId/workspace/search?q=...&path=...`

这些接口已具备 workspace 相对路径规范化、项目边界校验、忽略目录处理和文本预览保护，前端需要补齐 `api.listWorkspaceDirectory` 与 `api.getWorkspaceFilePreview` 封装。

### 新增图片 blob 接口

新增：

```text
GET /api/projects/:projectId/workspace/blob?path=<relativePath>
```

规则：

- 必须要求本地访问 token。
- 必须复用 workspace path 安全校验。
- 必须拒绝绝对路径、路径穿越、项目外路径、忽略路径和目录。
- 第一版只允许图片 MIME 类型。
- 返回 `Content-Type` 为对应图片类型。
- 可以增加保守大小限制，避免大文件直接进入浏览器。
- 不为 PDF、Office 和任意二进制开放。

## 样式与交互

视觉目标是工作台风格，不做营销化或大卡片化设计。

外层 tabs：

- 高度紧凑，贴合现有 `deepsea` UI。
- `对话记录` 和 `文件浏览器` 不显示关闭按钮。
- 不暴露拖出、分屏或 popout 入口。

文件浏览器：

- 左侧文件树宽度固定或可用 CSS clamp 控制。
- 右侧文件 tabs 与 viewer 填满剩余空间。
- 文件路径显示在 viewer header 中。
- 只读状态明确但不喧宾夺主。

文件 tabs：

- 显示文件名。
- hover 或选中时显示关闭按钮。
- tab title 使用完整 path。
- 排序仅限文件 tabset 内部。

## 错误处理

- 目录加载失败：树区域显示错误和重试按钮。
- 文件不存在：文件 tab 内显示“文件不存在或已被移动”。
- 路径被拒绝：显示安全错误，不暴露绝对路径细节。
- 忽略路径：显示“该路径不允许预览”。
- 文本过大或二进制：显示 `UnsupportedViewer`。
- 图片加载失败：显示图片错误状态和重试按钮。
- 空文件 tabs：显示“从左侧目录选择文件”。

## 风险与缓解

### FlexLayout 双层模型复杂度

风险：外层和内层都使用 FlexLayout，事件和样式可能互相影响。

缓解：外层只保留两个固定 tab；内层只保留单 tabset，并通过统一 helper 管理 model 创建与动作过滤。

### Monaco 体积和初始化成本

风险：Monaco 会增加前端包体和初始化成本。

缓解：文件浏览器 tab 激活后再加载 Monaco；文本 viewer 独立懒加载；图片和 unsupported viewer 不加载 Monaco。

### 文件树大目录性能

风险：大型仓库目录多，完整加载会慢。

缓解：目录树按需懒加载；复用后端目录限制；搜索走现有 workspace search。

### 图片 blob 安全边界

风险：新增 blob 接口可能扩大本地文件读取面。

缓解：只允许项目内图片 MIME；复用现有路径解析和忽略路径规则；拒绝任意二进制下载。

## 验收标准

1. 会话页中间区域有两个外层固定 tab：`对话记录`、`文件浏览器`。
2. `对话记录` tab 保留现有消息流和输入体验。
3. `文件浏览器` tab 左侧常驻目录树，右侧有文件 tabs。
4. 点击文件会打开或聚焦右侧对应文件 tab。
5. 同一路径不会重复打开多个 tab。
6. 文件 tabs 可关闭、可排序，但不能分屏。
7. 代码/文本文件通过 Monaco 只读显示。
8. 图片文件通过图片 viewer 显示。
9. PDF、Office 等不支持预览文件显示明确占位，并保留 viewer 扩展入口。
10. 左侧项目/会话树、右侧 Inspector、底部状态栏不被重构。
11. 新增图片 blob 接口通过安全边界测试。
12. `npm run build` 通过。

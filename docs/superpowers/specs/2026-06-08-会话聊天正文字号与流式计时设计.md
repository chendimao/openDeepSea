# 会话聊天正文字号与流式计时设计

## 目标

会话聊天区需要更紧凑、更准确地表达智能体运行状态。本次设计只调整会话聊天正文层，不扩大到左侧会话树、右侧 inspector、底部状态栏或消息头部 metadata。

核心目标：

- 将聊天正文和 Markdown 内容整体再小一号。
- 智能体正在流式回复时，在回复文本末尾显示闪烁等待光标。
- 思考计时按真实思考阶段累计：未开始回复时按秒递增，开始回复后停止。
- 如果前端显示时间与实际智能体思考时间存在误差，以实际事件时间为准。

## 范围

纳入范围：

- `packages/frontend/src/session-ui/SessionShellView.tsx`
- `packages/frontend/src/session-ui/session-os.css`
- `packages/frontend/src/session-ui/SessionShell.test.tsx`

不纳入范围：

- 不调整角色标签、时间、状态 badge、附件名、Markdown 显示切换按钮字号。
- 不调整左侧项目/会话树、右侧 inspector、底部状态栏。
- 不修改后端数据库 schema 或 WebSocket 协议。
- 不重构会话运行模型。

## 当前行为

聊天正文当前主要由 `.deepsea-message-body`、`.deepsea-run-log-body`、`.message-content`、`.markdown-preview` 等 CSS 规则控制，主体字号为 `14px / 20px`。

思考时长由 `getSessionRunThinkingDuration` 计算，活动状态使用 `Date.now()`，但组件没有稳定的秒级刷新来源。如果没有新的 WebSocket 事件触发 React 渲染，页面上的“思考中 Ns”不会每秒更新。

当前 active 判断包含 `paused`，这会让暂停状态也被视为仍在增长的思考中。用户期望是“回复就是停止”，即一旦智能体进入 answer 流式输出阶段，思考计时就应停止。

## 推荐方案

采用基于 ACP agent event 的前端实际思考时间计算。

时间规则：

1. 思考开始时间使用 `run.started_at`。
2. 思考结束时间优先使用该 run 第一条 `channel === 'answer'` 且内容非空的 `SessionAgentEvent.created_at`。
3. 如果还没有 answer 且 run 状态为 `queued`、`running` 或 `retrying`，结束时间使用当前前端 tick 的 `now`。
4. 如果 run 已结束但没有 answer，结束时间使用 `run.completed_at ?? run.updated_at`。
5. `paused`、`completed`、`failed`、`cancelled`、`interrupted` 不继续按前端当前时间增长。

显示规则：

- 没有 answer 且 run 仍活动：显示 `思考中 Ns`。
- 已经出现 answer：显示 `思考 Ns`，不再跳秒。
- 已结束但没有 answer：显示 `思考 Ns`，使用最终 run 时间兜底。
- 计时格式继续沿用当前 `s`、`m s`、`h m` 格式。

## UI 行为

### 正文字号

只将聊天正文和 Markdown 内容降一号：

- 从 `14px / 20px` 调整为 `13px / 19px`。
- 代码块、列表、引用、标题等 Markdown 子元素应继承或跟随正文比例，不把标题放大到破坏紧凑性。
- 消息头部、状态 badge、附件信息保持现状。

### 流式等待光标

智能体 run 处于 `queued`、`running` 或 `retrying` 时，回复区域显示闪烁光标：

- 如果已经有 answer 文本，光标显示在最后一段文本末尾。
- 如果还没有 answer 文本，显示在 `等待智能体输出...` 后。
- run 进入 `completed`、`failed`、`cancelled`、`paused` 或 `interrupted` 后，光标消失。
- 光标使用 CSS animation 实现，避免 JS 操作 DOM。

## 组件设计

### 秒级 tick

在 `TranscriptCanvas` 中维护一个轻量 `nowTick`：

- 仅当 timeline 中存在 `queued`、`running` 或 `retrying` run 时启动 `setInterval`。
- tick 间隔为 1000ms。
- 无活动 run 时清理 interval。
- `nowTick` 传入 `ThinkingDurationBadge`，保证前端在无新 WebSocket 事件时仍能按秒刷新。

### 思考时长计算

将 `getSessionRunThinkingDuration` 扩展为接收该 run 的 `agentEvents`：

```ts
getSessionRunThinkingDuration(run, agentEvents, now)
```

函数职责：

- 找到第一条 answer 事件。
- 根据 answer 是否存在和 run 状态决定 active。
- 返回 `{ label, active }`。

### 流式正文光标

`SessionRunTimeline` 接收 `streaming` 参数：

```ts
<SessionRunTimeline events={runAgentEvents} fallbackText={output} streaming={isRunStreaming(run)} />
```

实现策略：

- `buildSessionRunTranscriptItems` 仍只负责构建文本和事件 item，不混入 UI 状态。
- `SessionRunTimeline` 复用 `MessageContent` 的 `streaming` 能力，在最后一个文本 item 的实际文本 / Markdown 末尾追加通用 `streaming-cursor`。
- 如果没有文本 item 且 streaming 为 true，fallback 文本中也显示光标。

## 错误与边界

- 如果 event 时间乱序，按 `created_at` 和 `seq` 排序选择最早 answer。
- 如果 answer 事件缺失但 `stdout` 已有内容，仍使用 run 的最终时间兜底，避免显示为永久 active。
- 如果 `started_at` 非法，继续不渲染时长 badge。
- 如果 run 被取消或中断，输出使用现有 `runOutputText` 文案，且不显示流式光标。

## 测试计划

新增或调整 `SessionShell.test.tsx` 覆盖：

- 聊天正文 CSS 由 `14px / 20px` 调整为 `13px / 19px`。
- running run 没有 answer 时，`getSessionRunThinkingDuration` 使用传入 `now` 递增并显示 `思考中`。
- running run 已有 answer 时，使用第一条 answer 事件时间停止计时并显示 `思考`。
- active run 正文显示通用 `streaming-cursor`。
- completed run 不显示流式光标。
- paused run 不再作为 active thinking 继续增长。

最终验证：

- 运行前端相关测试。
- 运行 `npm run build` 作为仓库最低验证门禁。

## 验收标准

- 会话聊天正文和 Markdown 内容明显比当前小一号，消息头部 metadata 不变化。
- 智能体等待输出或流式回复期间有可见闪烁光标。
- 思考计时在没有 answer 前按秒增长。
- 第一条 answer 到达后，思考计时停止并保持稳定。
- 结束、暂停、取消、中断状态不会继续以当前时间增长。
- 相关测试和构建验证结果如实记录。

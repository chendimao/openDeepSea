# 聊天化 workflow 动态监控设计

## 背景

当前 Session 聊天页把 `Workflow Mission` 作为顶部独立大模块展示，导致中心聊天区被全局 workflow 面板打断。用户期望开发流程全程以聊天消息方式呈现，参考 Stitch 设计稿「深海指挥中心 - 动态监控增强版 (4:3)」，但保留右侧 Workflow 状态栏作为辅助信息面板。

## 目标

1. 移除中心区顶部 `Workflow Mission` 独立模块。
2. 将 workflow 主流程转为聊天消息流中的特殊消息。
3. 连续的 workflow 消息合并为一个消息组，避免同类短消息刷屏。
4. 每条 agent run 内部继续展示执行链路，但与聊天消息视觉统一。
5. 保留右侧状态栏、契约、计划、工具、运行等辅助模块。

## 非目标

1. 不重写 backend workflow 数据模型。
2. 不删除右侧 Workflow 状态栏。
3. 不改变 artifact 确认、请求修改、retry、复制、保存知识等行为。
4. 不把普通 assistant markdown 输出改成 workflow 卡片。

## 参考设计提炼

Stitch「动态监控增强版」中心区的关键特征：

1. 主流程在「对话记录 Transcript」中推进，不使用顶部全局流程板。
2. 用户消息、Planner 消息、assistant 消息按时间自然排列。
3. Planner workflow 消息内部包含：
   - 身份徽标、时间、状态 pill。
   - 自然语言摘要。
   - `Parallel Execution 并行执行` 阶段标签。
   - 节点式执行链路，含状态点、流动连接线、小型 agent/code 卡。
4. 右侧仍保留状态、契约、会话计划、实时监控、执行链路、待提交变更等辅助模块。

## 信息架构

中心聊天区只保留一条主叙事线：

1. 用户消息：保持普通聊天气泡。
2. Workflow 消息组：由 `workflowController`、`workflowGates`、`workflowArtifacts`、`workflowAgentAssignments` 以及 workflow 类 system/assistant 消息生成。
3. Agent run 消息：每条 run 仍作为 assistant 消息，但内部采用动态监控卡表达执行链。
4. 普通 assistant 输出：保持 markdown 正文优先。

右侧栏继续提供全局辅助视图，不参与主叙事。

## Workflow 消息组

### 合并规则

连续 workflow 消息必须合并为一个消息组：

1. 相邻消息都属于 workflow 类消息时合并。
2. workflow 类消息包括：
   - sender 或 role 表示工作流、planner、controller 的系统消息。
   - metadata 中含 workflow artifact、workflow gate、workflow controller 信息的消息。
   - 内容以「子任务」「产品经理检测」「诊断」「决策」「恢复次数」等 workflow 状态模板为主的消息。
3. 合并边界：
   - 遇到用户消息，结束当前 workflow 组。
   - 遇到普通 assistant 正文输出，结束当前 workflow 组。
   - 遇到 agent run，结束当前 workflow 组。
4. 同一 workflow 组内部按原时间排序，展示为紧凑事件行。

### 组内结构

Workflow 消息组显示为一条聊天消息：

1. 头部：
   - 徽标：`工作流` 或 `Planner`。
   - 首条和末条时间范围。
   - 状态：`等待确认`、`执行中`、`阻塞`、`已完成`。
   - 操作：复制、展开/收起。
2. 摘要：
   - 从 controller next_action、blocker、最新 workflow 消息中提取一句中文摘要。
3. 动态监控主体：
   - 阶段轨道：分析、计划、分派、实现、审查、验收。
   - 当前阶段使用蓝色或琥珀状态点。
   - gate artifact 使用内嵌确认卡展示，保留「确认」「请求修改」。
   - assignments 展示为小型 agent 节点。
4. 事件列表：
   - 每条合并进来的 workflow 消息显示为一行。
   - 同类连续状态行折叠为「N 条工作流事件」摘要，可展开查看原文。

## Agent Run 消息

每条 agent run 消息内部分为三层：

1. 运行头部：
   - agent 名称、provider/model、phase、状态、耗时。
   - 保留复制、保存知识、打开设计预览、markdown 切换等操作。
2. 动态监控卡：
   - 执行链路：root/planner、agent、tool/edit/verify/error/done 节点。
   - 实时活动：最新工具调用、文件读取、编辑、验证结果。
   - 小型 code preview 卡只展示短摘要，不复制完整 stdout。
3. 输出正文：
   - 真正的 assistant 回复仍在底部 markdown 正文中展示。
   - workflow 卡解释「发生了什么」，正文展示「回答了什么」，两者不重复。

## 视觉规则

1. 去掉中心区顶部 `Workflow Mission` 大面板。
2. workflow 主流程只出现在消息流中。
3. 使用现有 Deepsea 浅色高密度风格：
   - 低阴影、细边框、浅蓝/白色半透明层。
   - Inter 用于正文，JetBrains Mono 用于状态与技术元信息。
   - 状态色只表示语义：蓝色为 active/pending，绿色为完成，琥珀为等待或阻塞，红色为错误。
4. 消息内流程卡必须控制在消息宽度内。
5. 窄屏下执行链改为单列。
6. 动效只用于状态反馈：
   - active pulse。
   - 流动连线。
   - 进度条。
   - 必须支持 reduced motion 降级。

## 组件边界

主要改动文件预计为：

1. `packages/frontend/src/session-ui/SessionShellView.tsx`
   - 移除 transcript 外部的 `WorkflowMissionStrip` 渲染。
   - 新增 workflow 消息组 timeline item。
   - 新增 workflow 消息组渲染组件。
   - 调整 `RunFlowCapsule` 内部动态监控样式。
2. `packages/frontend/src/session-ui/session-os.css`
   - 删除或停用顶部 mission 大面板样式。
   - 新增消息内 workflow group、执行链、事件行、compact code card 样式。
3. `packages/frontend/src/session-ui/SessionShell.test.tsx`
   - 增加顶部 mission 不渲染断言。
   - 增加 workflow 连续消息合并断言。
   - 增加 agent run 内部动态监控断言。

## 数据流

1. `TranscriptCanvas` 继续接收 `SessionDetail`。
2. 构建 timeline 时，把现有 messages/runs 与 workflow summary 合并为同一条时间线。
3. workflow controller/gates/artifacts/assignments 生成一个当前状态消息组。
4. 连续 workflow 类 transcript messages 在 timeline 构建阶段合并为 `workflow-group` item。
5. 渲染层根据 item 类型选择：
   - `message`
   - `workflow-group`
   - `run`

## 边界情况

1. 没有 workflow 数据：不显示 workflow 消息组。
2. 有 workflow controller 但没有 assignments：显示等待分派，不显示空的 `0 agents` 大卡。
3. 有 pending gate：workflow 消息组内显示确认卡。
4. 有 blocker：workflow 消息组状态为阻塞，并显示 blocker 原因。
5. 当前 session 无 runs：不显示 agent run 动态监控。
6. 连续 workflow 消息很长：默认显示摘要和最近 3 条事件，其余折叠。

## 验收标准

1. 打开目标 session 页面，中心区顶部不再出现 `Workflow Mission` 独立模块。
2. workflow 主流程出现在聊天消息流中。
3. 连续的 `工作流` 消息合并为一条 workflow 消息组。
4. workflow 消息组内能看到阶段轨道、状态摘要、gate 操作。
5. agent run 消息内部展示执行链路和实时活动，但不重复 stdout 正文。
6. 右侧 Workflow 状态栏仍保留。
7. `SessionShell.test.tsx` 通过。
8. `npm run build -w @openclaw-room/frontend` 通过。
9. Playwright 截图确认中心聊天流清晰，不再被顶部 mission 大面板打断。

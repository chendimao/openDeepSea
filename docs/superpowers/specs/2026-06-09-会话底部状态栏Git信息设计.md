# 会话底部状态栏 Git 信息设计

## 背景

会话页面底部状态栏当前展示工作区路径、响应耗时、错误率、网络延迟、命令入口、上下文压力、Token 消耗和导出入口。后端会话状态快照已经提供 `status.git`，包含当前分支、改动文件数、是否存在未提交差异以及冲突风险。

本次需求是在底部状态栏中添加当前项目的 Git 信息，帮助用户快速确认“当前在哪个分支、工作区是否干净、是否存在冲突”。

## 已确认决策

- 采用轻量状态提示，不做展开面板和操作入口。
- 只显示本地 Git 状态，不读取远端 ahead / behind，不显示 commit SHA。
- Git 信息跟在当前路径后面，作为当前项目 / 会话上下文的一部分。
- 首选实现方案为前端展示增强，复用现有 `payload.status.git`。

## 目标

在会话页底部状态栏的路径区域追加 Git 状态，保持底部栏可扫读、低干扰，并避免新增后端数据契约。

目标显示形态：

```text
workspace / OpenDeepSea / 当前会话 · feat/session-os · 4 changed
```

当工作区干净时显示：

```text
workspace / OpenDeepSea / 当前会话 · feat/session-os · clean
```

当存在冲突风险时优先显示：

```text
workspace / OpenDeepSea / 当前会话 · feat/session-os · conflicts
```

## 非目标

- 不增加 Git 操作按钮，例如刷新、复制分支、打开 diff。
- 不增加 hover / click 展开详情。
- 不新增独立 Git status API。
- 不把 Git 字段复制到 `bottomStatus`。
- 不读取 remote、upstream、ahead / behind 或 commit SHA。

## 架构

本设计沿用现有会话工作区数据流：

1. 后端 `buildSessionStatus` 读取当前 session 对应 workspace 的本地 Git 状态。
2. 后端将结果放入 `SessionWorkspacePayload.status.git`。
3. 前端 `SessionShellView` 中的 `BottomStatusBar` 从 `payload.status.git` 读取字段。
4. 底部栏路径区域渲染 Git 分支和状态短文案。

该方案不改变 WebSocket 事件、REST payload 顶层结构或 `SessionBottomStatus` 类型。

## 组件边界

### `BottomStatusBar`

职责：

- 继续负责底部状态栏整体布局。
- 在路径组内追加一个 Git 状态片段。
- 根据 `payload.status.git` 派生展示文案。

建议拆出本地纯函数：

- `formatBottomGitState(git)`：返回 `clean`、`{n} changed` 或 `conflicts`。
- `formatBottomGitBranch(branchName)`：返回分支名，空值时返回 `detached`。

### CSS

在 `session-os-system.css` 中新增或复用路径区域内的轻量 chip 样式。

约束：

- 不新增高度。
- 不挤压右侧命令区。
- 分支名和状态文案均允许省略号截断。
- 小屏下跟随现有底部栏换行规则。

## 显示规则

Git 状态优先级：

1. `conflictRisk === 'high'`：显示 `conflicts`。
2. `changedFileCount > 0`：显示 `{changedFileCount} changed`。
3. 其他情况：显示 `clean`。

分支显示规则：

- `branchName` 有值：显示分支名。
- `branchName` 无值：显示 `detached`，避免用户误以为当前 Git 状态不可用。

颜色只作为辅助，不作为唯一信息：

- `clean` 使用弱化状态。
- `changed` 使用普通强调。
- `conflicts` 使用警示强调，并保留文本。

## 错误处理

后端当前 Git 读取失败时会回退到空分支和零改动。前端不额外抛错：

- 无分支名时显示 `detached`。
- 改动数为 `0` 且无冲突时显示 `clean`。
- 不在 UI 中展示 Git 命令错误，避免底部栏承担诊断职责。

## 可访问性

- Git 状态片段应有清晰文本，不只依赖颜色。
- 可为片段添加 `title`，包含完整分支名和状态，例如 `Git: feat/session-os, 4 changed`。
- 不新增不可达的 icon-only 控件，因为本次不做操作入口。

## 测试策略

前端渲染测试覆盖：

- 有分支且 `changedFileCount > 0` 时显示分支名和 `{n} changed`。
- `changedFileCount === 0` 且无冲突时显示 `clean`。
- `conflictRisk === 'high'` 时显示 `conflicts`，并优先于改动数量。
- 分支名为空时显示 `detached`。

最终验证：

- 执行相关前端测试。
- 执行 `npm run build` 作为仓库最低验证门禁。

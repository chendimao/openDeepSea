# 会话文件浏览器编辑工作台设计

日期：2026-06-09

## 背景

会话中间区的文件浏览器目前已经具备项目目录树、文件 tab、文本文件预览、图片预览和 Monaco 搜索样式。现有能力仍偏向只读预览：文件树没有独立的文件或文件夹选中状态，右上角新建文件夹和新建文件图标只是视觉元素，右侧 Monaco 仍是只读预览，文件树也没有右键菜单。

本设计将文件浏览器升级为轻量本地代码编辑工作台，支持真实磁盘写入、显式保存、文件树右键操作和未保存确认流。用户已确认以下关键决策：

- 保存采用显式保存：用户编辑后必须通过保存按钮或 `Cmd/Ctrl+S` 写入磁盘。
- 删除采用永久删除并二次确认。
- 新建和重命名遇到同名路径时禁止覆盖并提示重名。
- 未保存修改遇到关闭、删除、重命名、切换项目或刷新时，使用“保存 / 放弃 / 取消”确认流。
- 实现路线采用“小型本地 IDE 路线”，一次性设计完整能力，实施时分任务落地。

## 目标

1. 文件树支持文件和文件夹的真实选中状态。
2. 文件树右上角新建文件夹和新建文件按钮真实可用。
3. 新建目标目录遵循选中状态：选中文件夹则在该文件夹下新建，选中文件则在其父目录下新建，没有选择则在项目根目录新建。
4. 右侧文本文件预览区域升级为可编辑 Monaco 编辑器。
5. 文本编辑采用显式保存，并保留 dirty 状态和保存反馈。
6. 文件树提供右键菜单，支持文件或文件夹的创建、重命名、删除、复制相对路径等操作。
7. 所有真实文件系统写操作都受项目根目录、路径归一化、ignored path、symlink、防穿越和本地访问权限保护。
8. 删除和未保存修改相关操作必须有明确确认流程，避免误删或丢内容。

## 非目标

- 不实现跨目录拖拽移动。
- 不实现多文件并排 diff 或 merge。
- 不实现自动保存。
- 不实现 Git 状态标记。
- 不实现废纸篓或回收站恢复。
- 不实现二进制文件编辑。
- 不实现复杂权限模型，继续使用现有本地访问校验。

## 当前代码边界

当前前端相关模块：

- `packages/frontend/src/session-ui/FileBrowserWorkspace.tsx`：持有文件 tab 和 active path。
- `packages/frontend/src/session-ui/WorkspaceFileTree.tsx`：目录树、目录懒加载、文件打开、树搜索。
- `packages/frontend/src/session-ui/FileViewers.tsx`：文本 Monaco 预览、图片预览和不支持状态。
- `packages/frontend/src/session-ui/WorkspaceFileTabs.tsx`：文件 tab 布局和关闭、聚焦、拖拽排序。
- `packages/frontend/src/session-ui/workspace-file-model.ts`：tab 创建、关闭、排序和 viewer 类型判断。

当前后端相关模块：

- `packages/backend/src/workspace-files.ts`：目录读取、路径解析、文件预览、图片 blob、搜索和安全校验。
- `packages/backend/src/routes.ts`：workspace tree、file、blob、search 读接口。
- `packages/frontend/src/lib/api.ts` 和 `packages/frontend/src/lib/types.ts`：前端 API 和类型。

当前后端只有读接口：

- `GET /projects/:projectId/workspace/tree`
- `GET /projects/:projectId/workspace/file`
- `GET /projects/:projectId/workspace/blob`
- `GET /projects/:projectId/workspace/search`

## 后端设计

### 安全原则

新增写接口必须复用并扩展现有 workspace 文件安全模型：

- 所有接口先执行 `requireLocalAccess`。
- 所有项目通过 `projectRepo.get(projectId)` 获取本地项目路径。
- 所有用户输入路径先经过 `normalizeWorkspacePath`。
- 所有目标路径必须通过 `resolveWorkspacePath` 或同等安全解析，保证在项目根目录内。
- 禁止路径穿越、绝对路径、`\0`、symlink 目录、项目外路径。
- 禁止操作 ignored path，包括 `.git`、`node_modules`、`dist`、`build`、`.next`、`.turbo`、`coverage` 和设置里的额外 ignored dirs。
- 禁止创建 ignored 文件名，例如 `.env`。
- 所有写接口返回明确错误码，不返回本机绝对路径。

### 文件名校验

新增 `validateWorkspaceEntryName(name)`：

- 禁止空字符串。
- 禁止 `.` 和 `..`。
- 禁止包含 `/`、`\`、`\0`。
- 禁止创建后命中 ignored path 或 ignored file name。
- 同名存在时返回 `WORKSPACE_PATH_EXISTS`。
- 暂不增加 Windows 保留名校验，后续如需要跨平台强约束再补。

### 新增错误码

在 `WorkspaceFileErrorCode` 中补充：

- `WORKSPACE_PATH_EXISTS`
- `WORKSPACE_ENTRY_NAME_INVALID`
- `WORKSPACE_FILE_CONFLICT`

保留既有错误码：

- `WORKSPACE_PATH_INVALID`
- `WORKSPACE_PATH_ABSOLUTE`
- `WORKSPACE_PATH_TRAVERSAL`
- `WORKSPACE_PATH_NOT_FOUND`
- `WORKSPACE_PATH_NOT_DIRECTORY`
- `WORKSPACE_PATH_NOT_FILE`
- `WORKSPACE_PATH_SYMLINK`
- `WORKSPACE_PATH_OUTSIDE_PROJECT`
- `WORKSPACE_PATH_IGNORED`
- `WORKSPACE_FILE_BINARY`
- `WORKSPACE_FILE_TOO_LARGE`
- `WORKSPACE_SEARCH_QUERY_INVALID`

错误状态建议：

- `400`：路径或名称非法。
- `403`：ignored、symlink、项目外路径。
- `404`：目标不存在。
- `409`：同名冲突或文件外部修改冲突。

### 新增接口

#### 创建文件

`POST /projects/:projectId/workspace/file`

请求：

```json
{
  "parentPath": "src",
  "name": "new-file.ts",
  "content": ""
}
```

行为：

- `parentPath` 为空表示项目根目录。
- 确认 `parentPath` 是可访问目录。
- 在父目录下创建文件。
- `content` 可选，默认空字符串。
- 同名存在返回 `409 WORKSPACE_PATH_EXISTS`。
- 创建成功返回新建 entry。

响应：

```json
{
  "entry": {
    "name": "new-file.ts",
    "path": "src/new-file.ts",
    "type": "file",
    "size": 0,
    "mimeType": "text/plain",
    "language": "typescript"
  }
}
```

#### 创建文件夹

`POST /projects/:projectId/workspace/directory`

请求：

```json
{
  "parentPath": "src",
  "name": "components"
}
```

行为：

- 确认 `parentPath` 是可访问目录。
- 创建一级文件夹，不递归创建多级目录。
- 同名存在返回 `409 WORKSPACE_PATH_EXISTS`。
- 创建成功返回新建 entry。

#### 保存文本文件

`PUT /projects/:projectId/workspace/file`

请求：

```json
{
  "path": "src/App.tsx",
  "content": "...",
  "expectedMtimeMs": 1760000000000
}
```

行为：

- 只保存文本文件。
- 保存前再次读取文件 stat。
- 如果传入 `expectedMtimeMs` 且当前磁盘 `mtimeMs` 已变化，返回 `409 WORKSPACE_FILE_CONFLICT`。
- 保存成功后返回最新 preview，包括 `mtimeMs`。
- 如果用户选择强制覆盖，前端再次调用保存接口并显式传 `force: true`，后端跳过 mtime 冲突检查。

响应：

```json
{
  "path": "src/App.tsx",
  "content": "...",
  "truncated": false,
  "language": "typescript",
  "mimeType": "text/plain",
  "size": 1234,
  "mtimeMs": 1760000000100
}
```

#### 重命名 entry

`PATCH /projects/:projectId/workspace/entry`

请求：

```json
{
  "path": "src/old-name.ts",
  "name": "new-name.ts"
}
```

行为：

- 支持文件和文件夹。
- 只改同级名称，不做跨目录移动。
- 同名存在返回 `409 WORKSPACE_PATH_EXISTS`。
- 重命名成功返回旧路径、新路径和新 entry。

响应：

```json
{
  "oldPath": "src/old-name.ts",
  "newPath": "src/new-name.ts",
  "entry": {
    "name": "new-name.ts",
    "path": "src/new-name.ts",
    "type": "file",
    "size": 1234,
    "mimeType": "text/plain",
    "language": "typescript"
  }
}
```

#### 删除 entry

`DELETE /projects/:projectId/workspace/entry`

请求：

```json
{
  "path": "src/components"
}
```

行为：

- 支持文件和文件夹。
- 文件夹允许非空永久删除。
- 删除前端必须二次确认。
- 后端仍做全部路径安全校验。
- 成功返回 `204`。

## 前端状态设计

### 核心状态

`FileBrowserWorkspace.tsx` 升级为文件浏览器协调层，统一持有：

- `tabs: WorkspaceFileTab[]`
- `activePath: string | null`
- `selectedEntryPath: string | null`
- `selectedEntryType: 'file' | 'directory' | null`
- `dirtyByPath: Record<string, DirtyFileState>`
- `pendingAction: PendingWorkspaceAction | null`
- `confirmState: WorkspaceConfirmState | null`

`activePath` 表示右侧当前打开的文件，`selectedEntryPath` 表示文件树当前选择目标。两者可以相同，也可以不同。

### DirtyFileState

```ts
interface DirtyFileState {
  path: string;
  savedContent: string;
  draftContent: string;
  mtimeMs: number | null;
  saving: boolean;
  saveError: string | null;
}
```

规则：

- `dirty = draftContent !== savedContent`。
- 保存成功后 `savedContent = draftContent`，更新 `mtimeMs`，清除 `saveError`。
- 保存失败保留 draft，不丢内容。

### 新增纯函数模块

新增 `workspace-file-operations.ts`，承载不依赖 React 的可测逻辑：

- `resolveCreateParentPath(selectedEntry, treeItems)`：根据选中 entry 计算新建父目录。
- `validateEntryNameInput(name)`：前端即时校验名称。
- `renameTabPaths(tabs, oldPath, newPath, entryType)`：重命名文件或文件夹后更新 tab。
- `closeDeletedTabs(tabs, deletedPath, entryType)`：删除文件或文件夹后关闭受影响 tab。
- `findDirtyFilesUnderPath(dirtyByPath, path, entryType)`：找出会被删除或重命名影响的 dirty 文件。
- `shouldBlockForDirty(action, dirtyByPath)`：判断操作是否需要保存/放弃/取消确认。

## 文件树交互设计

### 选中状态

文件树从“只高亮 active file”升级为两个状态：

- active file：右侧当前编辑 tab，对应用更强蓝色文字或右侧蓝色边。
- selected entry：文件树当前操作目标，对应用浅蓝底或细描边。

交互规则：

- 点击文件：选中文件，并打开到右侧 tab。
- 点击文件夹：选中文件夹，并展开或收起。
- 右键文件或文件夹：先选中该 entry，再打开上下文菜单。
- 文件树空白区域右键：清空 selected entry，菜单目标为根目录。
- 搜索过滤时仍保留 selected entry；如果 selected entry 不在过滤结果里，操作目标仍按 selected entry，但视觉上可以不显示。

### 顶部新建按钮

右上角新建文件夹和新建文件图标变成真实按钮：

- 选中文件夹：在该文件夹下新建。
- 选中文件：在该文件父目录下新建。
- 没有选择：在项目根目录新建。

新建使用文件树内 inline 输入：

- Enter 确认。
- Esc 取消。
- Blur 不自动提交。
- 重名或非法名称显示错误，输入不关闭。

成功行为：

- 新建文件：刷新父目录，自动打开并选中新文件。
- 新建文件夹：刷新父目录，自动展开并选中新文件夹。

### 右键菜单

文件菜单：

- 打开
- 保存，仅 dirty 文件启用
- 重命名
- 删除
- 新建文件
- 新建文件夹
- 复制相对路径

文件夹菜单：

- 新建文件
- 新建文件夹
- 重命名
- 删除
- 复制相对路径

空白区域菜单：

- 新建文件
- 新建文件夹
- 刷新根目录

实现建议：

- 优先复用项目现有 Radix 菜单风格。
- 如果缺少 `@radix-ui/react-context-menu`，可新增该依赖，或用现有 DropdownMenu 结合 fixed position 实现。
- 菜单在文件树滚动容器内不能被裁剪，需要 portal 或 fixed 定位。

### 重命名

重命名使用 inline 输入：

- 文件和文件夹都只改名称，不移动目录。
- Enter 确认。
- Esc 取消。
- Blur 不自动提交。
- 同名返回错误，不覆盖。

重命名成功后：

- 文件：刷新父目录，更新打开 tab 的 path。
- 文件夹：刷新父目录，更新所有位于该目录下的打开 tab path。
- dirty map 同步迁移到新路径。

### 删除

删除采用永久删除并二次确认：

- 文件确认文案显示相对路径。
- 文件夹确认文案显示“将永久删除该文件夹及其内容”。
- 删除成功后刷新父目录。
- 删除文件时关闭对应 tab。
- 删除文件夹时关闭该目录下所有 tab。
- 如果删除目标覆盖 dirty 文件，先进入未保存确认流。

## 可编辑 Monaco 设计

### 编辑器行为

文本文件使用 Monaco 编辑器：

- `readOnly: false`
- 继续使用当前 light theme。
- 继续支持 Monaco 原生搜索。
- 文本文件加载后建立 dirty state。
- 图片文件继续保持预览。
- 不支持文件和二进制文件继续显示不支持状态。

### 保存入口

保存动作：

- `Cmd/Ctrl+S` 保存当前 active tab。
- 编辑器工具行显示保存按钮。
- 文件右键菜单可保存 dirty 文件。

保存流程：

1. 用户触发保存。
2. 前端读取 active path 的 dirty state。
3. 调用 `PUT /workspace/file`，传 `path`、`content`、`expectedMtimeMs`。
4. 保存成功后更新 `savedContent`、`mtimeMs`，清除 dirty。
5. 保存失败后保留 draft 并显示错误。

### 冲突处理

如果后端返回 `WORKSPACE_FILE_CONFLICT`：

- 弹出冲突 Dialog：`磁盘文件已被外部修改`。
- 操作：
  - `重新加载磁盘版本`：丢弃当前 draft，重新拉取文件。
  - `强制覆盖`：再次保存并传 `force: true`。
  - `取消`：保留当前 draft。

初期不做 merge。

### 编辑器工具行

在 tab bar 下方或编辑器顶部增加轻量工具行：

- 当前相对路径。
- dirty 状态。
- 保存按钮。
- 重新加载按钮。
- 保存中、保存失败提示。

工具行保持紧凑，不做营销式说明文案。

## 未保存确认流

当用户执行以下操作且影响 dirty 文件时触发：

- 关闭 dirty tab。
- 删除 dirty 文件。
- 删除包含 dirty 文件的文件夹。
- 重命名 dirty 文件。
- 重命名包含 dirty 文件的文件夹。
- 切换项目。
- 浏览器刷新或关闭页面。

单文件确认：

- `保存`：先保存，成功后继续原动作。
- `放弃`：丢弃 draft，继续原动作。
- `取消`：中断原动作。

多文件确认：

- Dialog 列出最多 5 个 dirty 文件，超过显示 `还有 N 个文件`。
- `保存全部并继续`
- `放弃全部并继续`
- `取消`

浏览器刷新或关闭页面：

- 使用 `beforeunload` 提示用户存在未保存修改。
- 浏览器原生确认无法自定义按钮文案，这是平台限制。

## 缓存和数据同步

操作成功后刷新规则：

- 新建文件：刷新目标父目录，打开并选中新文件。
- 新建文件夹：刷新目标父目录，展开并选中新文件夹。
- 重命名文件：刷新父目录，更新 tab path，迁移 dirty state。
- 重命名文件夹：刷新父目录，更新所有受影响 tab path，迁移 dirty state。
- 删除文件：刷新父目录，关闭对应 tab，清理 dirty state。
- 删除文件夹：刷新父目录，关闭目录下所有 tab，清理相关 dirty state。
- 保存文件：更新 preview query 或本地 preview 状态，清除 dirty。

React Query key 建议：

- `['workspace-tree', projectId, parentPath]`
- `['workspace-file-preview', projectId, path]`
- 写操作成功后精准 invalidate 相关 key。

## UI 和视觉要求

整体保持现有 Stitch 风格：

- 左侧文件树继续使用浅色、紧凑、代码编辑器风格。
- active file 和 selected entry 需要区分但不能冲突。
- 右键菜单样式使用浅色半透明面板、8px 以内圆角、紧凑行高。
- 危险操作使用明确红色文字或图标。
- 保存失败和重名错误使用局部 inline 提示，避免全局 toast 淹没上下文。
- toolbar 使用图标按钮加 tooltip，避免大量说明文字。
- 所有输入框文字不能溢出。
- 键盘焦点清晰可见。

## 实施计划边界

虽然目标设计是完整编辑工作台，但实施建议拆成四个任务：

1. 后端 workspace 写操作 API 和测试。
2. 前端文件树选中态、新建、右键菜单、重命名和删除。
3. Monaco 可编辑、dirty、显式保存和冲突处理。
4. 未保存确认流、浏览器 smoke 和视觉 polish。

每个任务完成后都需要独立验证。最终合并前运行前端 build、相关后端测试、前端 model 测试和浏览器 smoke。

## 风险和处理

- 真实磁盘写入风险：通过显式保存、永久删除二次确认、路径安全校验和重名禁止覆盖降低风险。
- 外部编辑冲突：通过 `mtimeMs` 检测并提示用户选择重新加载或强制覆盖。
- 状态复杂度上升：用 `FileBrowserWorkspace` 作为协调层，关键路径抽到纯函数测试。
- 文件夹删除影响多个 tab：先计算受影响 tab 和 dirty 文件，再执行确认和关闭。
- ContextMenu 被滚动容器裁剪：使用 portal 或 fixed 定位。
- Monaco 保存快捷键和浏览器默认保存冲突：编辑器捕获 `Cmd/Ctrl+S` 并阻止浏览器默认保存页面。

## 验收清单

- 文件树点击文件和文件夹都有选中态。
- 顶部新建文件和新建文件夹真实可用。
- 选中文件夹时在该文件夹下新建。
- 选中文件时在其父目录下新建。
- 无选择时在根目录新建。
- 文件树右键菜单可对文件和文件夹执行新建、重命名、删除、复制相对路径。

- 删除永久删除且必须二次确认。
- 文本文件右侧可编辑。
- `Cmd/Ctrl+S` 可保存当前文件。
- dirty tab 和文件树 dirty 文件有清晰状态。
- 未保存关闭、删除、重命名、切项目和刷新触发保存 / 放弃 / 取消。
- 保存失败不丢 draft。
- 外部修改冲突后可取消、重新加载或强制覆盖。

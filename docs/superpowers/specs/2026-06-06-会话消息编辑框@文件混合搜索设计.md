# 会话消息编辑框 `@` 文件混合搜索设计

- 日期：2026-06-06
- 范围：Session 工作台消息编辑框、`PromptArea` 触发器、Session WebSocket 消息协议、Session runtime 上下文注入
- 目标页面：`http://localhost:5173/projects/Vn4n0-cIzLST/sessions/H6ifd350E2yL-oge`

## 1. 背景与现状

当前 Session 工作台底部输入区在 `packages/frontend/src/session-ui/SessionShellView.tsx` 中由 `DeepseaComposer` 渲染，实际是普通 `<input>`。placeholder 写有“支持 @ 文件、# 历史、! 上下文”，但当前没有 `@` trigger、文件搜索、chip、结构化引用或后端上下文注入。

仓库已有可复用能力：

- `packages/frontend/src/components/prompt-area/`：已有 contentEditable 输入组件、trigger 检测、异步 `onSearch`、loading/error、chip、键盘选择和 popover。
- `api.searchWorkspaceFiles(projectId, query)`：对接 `GET /projects/:projectId/workspace/search`，返回工作区源码文件和目录路径。
- `api.listProjectFiles(projectId, { q })`：对接 `GET /projects/:projectId/files?q=`，返回项目资源库文件，包括上传文件和 `agent_document`。
- 后端 `workspace-file-refs.ts` 已能把工作区路径读取为 prompt 片段或图片路径；群聊消息已有 `metadata.file_refs` 的思路。
- `session_messages.metadata` 已存在，可存储 Session 消息的结构化引用数据。

当前缺口是：Session WebSocket 消息只有 `content`，runtime 只把正文传入 `buildRuntimePrompt`，所以即使 UI 插入 `@文件名` 文本，后端也无法可靠知道用户选中了哪些文件，更无法受控注入上下文。

## 2. 目标行为

1. 在 Session 消息编辑框输入 `@` 时弹出混合文件搜索下拉。
2. 搜索结果同时包含两类来源：
   - `Source`：项目工作区源码文件 / 目录，来自 workspace search。
   - `Library`：项目资源库文件，来自 project files search。
3. 结果按来源分组展示，并保留紧凑单行样式、图标和描述信息。
4. 选中结果后插入 chip；正文仍保持可读的 `@显示名`，方便用户发送前理解消息。
5. 发送时通过 WebSocket 额外传递结构化引用：
   - `workspaceFileRefs: string[]`
   - `libraryFileRefs: string[]`
6. 后端把结构化引用写入 `session_messages.metadata`，并在构建 runtime prompt 时注入受控上下文。
7. 上传文本文件默认不全文注入，只附 metadata；避免把资源库大文本直接塞进 prompt。

## 3. 不做

- 不实现完整文件管理器或复杂 picker。
- 不让上传文本文件默认全文注入 prompt。
- 不改变群聊 `@` 文件搜索已有行为。
- 不为 `# 历史`、`! 上下文` 做本次实现；只预留 `PromptArea` 继续扩展的空间。
- 不把工作区源码路径落库成 `ProjectFile`。

## 4. 前端设计

### 4.1 替换 Session 输入框

文件：

- `packages/frontend/src/session-ui/SessionShellView.tsx`
- 必要时拆出 `packages/frontend/src/session-ui/SessionFileComposer.tsx`

将 `DeepseaComposer` 从普通 `<input>` 改为 `PromptArea`：

- 使用受控 `Segment[]` 状态。
- `onSubmit` 读取 plain text 和 chip data。
- 保留现有 `.deepsea-composer` 视觉容器，避免破坏 SessionOS 布局。
- 发送成功后清空 segments。

### 4.2 混合 `@` trigger

新增 Session 专属搜索逻辑，推荐放在 Session UI 邻近文件中，避免污染群聊 composer：

- 输入空 `@`：不调用 workspace search（后端 `q` 要求非空）；仅展示最近创建或最近引用的少量 Library 结果，并提示“继续输入文件名以搜索 Source”。
- 输入非空 query：并发请求：
  - `api.searchWorkspaceFiles(projectId, query)`
  - `api.listProjectFiles(projectId, { q: query })`
- 搜索结果合并、去重和限量：
  - 每组最多 6 条，总数最多 12 条。
  - 同名时保留不同来源，但 description 明确显示路径或来源类型。
  - 目录可展示但默认不作为可注入内容；若选择目录，按“引用路径 metadata”处理，不递归注入目录内容。
- `TriggerSuggestion` 增加可选 `groupLabel?: string` 或等价字段；`TriggerPopover` 在相邻组变化时渲染只读组标题，不把组标题当作可选择 option。
- 分组渲染必须保持现有键盘导航语义：上下键只在可选择结果间移动，`aria-selected` 只用于真正的结果项。

### 4.3 chip 数据结构

`PromptArea` 的 `ChipSegment.data` 携带 Session 文件引用 payload：

```ts
type SessionFileReferenceChip =
  | {
      kind: 'workspace';
      path: string;
      name: string;
      entryType: 'file' | 'directory';
    }
  | {
      kind: 'library';
      fileId: string;
      name: string;
      sourceType: 'uploaded_file' | 'agent_document';
      mimeType: string;
      size: number;
    };
```

chip `value` 使用稳定引用值：

- workspace：`workspace:${path}`
- library：`library:${fileId}`

chip `displayText` 使用短名称；popover description 显示完整路径、来源、大小或类型。

### 4.4 发送 payload

前端 `onSendMessage` 的签名从 `content: string` 扩展为结构化输入：

```ts
type SessionComposerSubmit = {
  content: string;
  workspaceFileRefs?: string[];
  libraryFileRefs?: string[];
};
```

调用链需要同步扩展：

- `SessionShellView`
- `SessionShell`
- `SessionWorkspacePage.runSessionCommand`
- `sessionSocket.sendSessionMessage`
- `WsClientEvent`

普通 `/command` 仍只按 `content` 路由到 `session.command.run`，不附带文件引用。非命令消息走 `session.message.send`。

### 4.5 UI 状态与错误

- 搜索中显示 loading 行。
- 搜索失败显示错误行，不阻止继续输入。
- 无结果时显示“没有匹配的文件”。
- 搜索结果带 `Source` / `Library` 组标题。
- 已选择 chip 可删除，删除后发送 payload 自动移除对应引用。
- chip 被复制/粘贴时即使失去 data，也必须降级为普通文本，不应伪造引用。

## 5. 后端协议设计

### 5.1 WebSocket 客户端事件

`session.message.send` 扩展为：

```ts
{
  type: 'session.message.send';
  sessionId: string;
  content: string;
  agentId?: string;
  mode?: SessionMode;
  workspaceFileRefs?: string[];
  libraryFileRefs?: string[];
}
```

`session-socket-controller.ts` 的 schema 增加两个可选数组：

- `workspaceFileRefs`: 去重、trim、最大 12 条。
- `libraryFileRefs`: 去重、trim、最大 12 条。

### 5.2 消息 metadata

`dispatchSessionUserMessage` 增加入参：

```ts
workspaceFileRefs?: string[];
libraryFileRefs?: string[];
```

创建 `session_messages` 时写入：

```json
{
  "target_agent_id": "planner",
  "workspace_file_refs": ["packages/frontend/src/session-ui/SessionShellView.tsx"],
  "library_file_refs": ["asset:abc123", "file123"]
}
```

metadata 写入前必须做后端校验，不信任前端 chip data。

### 5.3 引用校验

workspace 引用：

- 使用 `normalizeWorkspacePath` / `resolveWorkspacePath` / `ensureWorkspacePathAllowed` 这一类既有安全规则。
- 拒绝绝对路径、越界路径、被忽略路径、不可访问路径。
- 目录引用可存入 metadata，但不注入目录内容。

library 引用：

- 使用 `fileRepo.get(id)` 获取。
- 要求文件存在、未删除、`project_id` 与 session 所属 project 一致。
- 无效 ID 忽略或返回错误需统一：推荐采用 400，避免用户以为引用已生效。

## 6. Runtime 上下文注入设计

### 6.1 总体预算

Session 文件引用不能直接复用 workspace 当前较大的 512KB/2MB 上限。新增 Session prompt 引用预算：

- 单个 workspace 文本文件最多 24KB。
- 所有自动注入文本合计最多 64KB。
- `agent_document` 单篇最多 16KB。
- Library 自动注入合计最多 32KB。
- 超出预算时截断，并在 prompt 中明确标注 `truncated`。

这些常量应放在后端 runtime 或独立 helper 中，便于测试。

### 6.2 Source 注入

workspace 文件：

- 文本文件：读取受限内容，插入 `## Referenced Source Files`。
- 图片文件：如 ACP runtime 支持 image paths，则作为图片路径传入；否则仅插入 metadata。
- 二进制文件：只插入 metadata，不注入正文。
- 目录：只插入 metadata，不递归读取。

### 6.3 Library 注入

`agent_document`：

- 注入受限 markdown 片段。
- 标注来源：agent、task、room、创建时间等已有字段。

上传文件：

- 默认只注入 metadata：文件名、MIME、大小、上传者、URL、来源上下文。
- 如果是图片，可作为图片路径或 metadata 处理，取决于现有上传文件是否有本地 `storage_path` 且 runtime 支持图片。
- 上传文本文件不自动全文注入。后续若需要，可另做显式“展开正文”动作。

### 6.4 Prompt 结构

`buildRuntimePrompt` 扩展为先构建引用上下文，再拼入 prompt：

```md
本轮 prompt 来源由 SessionOS Context Inspector 记录。

当前目标：...

## Context Sources
...

## Referenced Files

### Source: packages/frontend/src/session-ui/SessionShellView.tsx
...

### Library: session-design.md
...

### Library Metadata: handoff-notes.txt
- MIME: text/plain
- Size: 42KB
- Content not auto-injected.

## User Request
...
```

## 7. 数据流

```text
用户输入 @session
  ↓
PromptArea trigger 并发搜索 Source + Library
  ↓
按组展示候选，选中插入 chip
  ↓
发送时提取 content + workspaceFileRefs + libraryFileRefs
  ↓
session.message.send WebSocket 事件
  ↓
后端校验引用并写入 session_messages.metadata
  ↓
dispatchSessionUserMessage 构建 runtime prompt
  ↓
按预算注入 Source / Library 上下文
  ↓
runSessionAgent 执行
```

## 9. 风险与缓解

- **R1 上下文膨胀**：通过 Session 专属预算和上传文本 metadata-only 策略控制。
- **R2 前端 chip data 丢失**：发送时只从有效 chip data 生成结构化引用；粘贴得到的纯文本不自动变成引用。
- **R3 搜索结果过多**：按组限量，保留后端 search limit，不在 UI 一次展示全部。
- **R4 协议兼容**：新字段可选，旧客户端只发送 `content` 时行为不变。
- **R5 路径安全**：所有 workspace path 都以后端校验为准，前端只负责交互。
- **R6 Library 内容差异**：`agent_document` 有 `content`，上传文件可能只有 `storage_path` 或 URL，因此默认 metadata-only 更稳。

## 10. 验收标准

1. Session 消息编辑框可通过 `@` 混合搜索 Source 和 Library。
2. 搜索结果分组清晰，键盘选择和鼠标选择可用。
3. 选中结果插入 chip，发送后 payload 包含正确结构化引用。
4. 后端校验引用归属和路径安全，并写入 `session_messages.metadata`。
5. runtime prompt 自动注入 workspace 文本和 agent document 的受限内容。
6. 上传文本文件默认只注入 metadata，不全文注入。
7. 新字段保持向后兼容，不影响不带引用的普通 Session 消息。
8. 相关后端和前端定向测试覆盖通过。

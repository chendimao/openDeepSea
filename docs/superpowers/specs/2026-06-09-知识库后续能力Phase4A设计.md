# 知识库后续能力 Phase 4A 设计

- 日期：2026-06-09
- 来源设计：`docs/superpowers/specs/2026-06-07-资源页升级知识库设计.md`
- 前置状态：
  - Phase 1 已完成知识库页面、基础解析、FTS、详情、chunks、显式引用。
  - Phase 2 已完成 `openclaw:knowledge` Agent RAG 工具、citation 和 usage refs。
  - Phase 3 已完成 Session 消息保存为 `session_note` 知识笔记。
- 用户确认：按“方案 A：Phase 4A 后续能力最小闭环”推进。

## 1. 目标

Phase 4A 的目标是把 5 个未完成方向各自推进到可运行、可验证、可继续扩展的第一批闭环：

1. 高级检索：在现有 FTS 之外增加本地 hybrid/rerank 检索基线，并预留外部 embedding provider 接口。
2. 复杂文档解析增强：记录解析能力、解析质量和 sidecar 需求，让 PDF、Office、图片、表格等复杂资料有清晰状态，而不是静默变成空文本。
3. Agent RAG 增强：让 task、workflow、collaboration 等非普通聊天 agent 也能安全使用知识库工具，并让检索模式、citation 和 usage ref 可追踪。
4. 知识沉淀增强：提供重复、过期、解析不完整等治理信号，并允许用户编辑摘要、标签和结构化事实。
5. 导入与知识源扩展：支持手动知识、URL/web 页面记录、workspace 文档进入知识库。

## 2. 非目标

1. 不在本阶段接入云端 embedding API、外部向量数据库、GraphRAG 或实体关系图谱。
2. 不默认抓取任意 URL 内容，避免 SSRF、隐私和网络不稳定问题；URL/web 导入先以用户提供内容或 metadata 为准。
3. 不强制安装 Docling、Unstructured、OCR 或 Python sidecar。
4. 不把所有知识默认塞进 prompt；Agent 仍通过受控工具和 citation 使用知识。
5. 不做跨项目知识共享。
6. 不改变已有 `uploaded_file`、`agent_document`、`session_note` 的兼容语义。

## 3. 总体架构

Phase 4A 继续沿用现有知识库表和服务边界，新增少量专用服务，避免把所有逻辑堆进 `knowledgeRepo`：

- `knowledgeSearchService`：封装 keyword、vector_preview、hybrid 检索和 rerank 组合。
- `knowledgeEmbeddingService`：提供本地 hash embedding provider，并定义外部 provider 接口。
- `knowledgeParserCapabilities`：根据 mime、扩展名和解析结果输出 parser status、warnings、capabilities。
- `knowledgeImportService`：把 manual、url/web_page、workspace_doc 转成 `knowledge_sources`、extractions 和 chunks。
- `knowledgeGovernanceService`：计算重复、过期、metadata 缺失、parser incomplete 等治理信号。

前端仍以 `/knowledge` 为主入口，不新增独立页面。页面增加检索模式、导入入口、治理提示和详情扩展区，保持当前三栏工作台形态。

## 4. 高级检索设计

### 4.1 检索模式

新增检索模式：

```ts
type KnowledgeRetrievalMode = 'keyword' | 'vector_preview' | 'hybrid';
```

- `keyword`：沿用现有 FTS5，保持默认兼容。
- `vector_preview`：使用本地 `local-hash-v1` embedding provider 对 chunk 和 query 做确定性 hash 向量，计算 cosine similarity。它不是语义模型，只是本地可测试的向量检索骨架。
- `hybrid`：合并 FTS、local hash vector、标题/摘要/标签命中和最近更新信号，输出统一排序。

### 4.2 本地 embedding provider

本阶段新增 provider 接口：

```ts
interface KnowledgeEmbeddingProvider {
  id: string;
  model: string;
  dimensions: number;
  embed(text: string): number[];
}
```

默认实现：

- `id = local-hash`
- `model = local-hash-v1`
- `dimensions = 256`
- 输入文本按 token 归一化后做稳定 hash，累加到固定维度，再做 L2 normalize。

这个 provider 的价值是让索引、存储、vector 搜索、hybrid rerank 和测试先闭环。后续接 OpenAI、本地模型或 Ollama 时，只替换 provider，不改 API 和 UI。

### 4.3 数据模型

新增表：

```sql
CREATE TABLE knowledge_chunk_embeddings (
  id TEXT PRIMARY KEY,
  chunk_id TEXT NOT NULL UNIQUE,
  source_id TEXT NOT NULL,
  project_id TEXT NOT NULL,
  provider TEXT NOT NULL,
  model TEXT NOT NULL,
  dimensions INTEGER NOT NULL,
  vector_json TEXT NOT NULL,
  content_hash TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  FOREIGN KEY (chunk_id) REFERENCES knowledge_chunks(id) ON DELETE CASCADE,
  FOREIGN KEY (source_id) REFERENCES knowledge_sources(id) ON DELETE CASCADE
);
```

`knowledgeRepo.replaceChunks()` 写入 chunks 后触发本地 embedding upsert。禁用 source 不删除 embedding，但搜索时继续遵循 source status 和 chunk enabled。

### 4.4 Rerank 信号

搜索结果增加可选 ranking metadata：

```ts
interface KnowledgeRankingSignals {
  keywordScore?: number;
  vectorScore?: number;
  titleMatch: boolean;
  tagMatch: boolean;
  summaryMatch: boolean;
  recencyBoost: number;
  finalScore: number;
}
```

排序规则：

1. `keyword` 使用 FTS bm25 顺序。
2. `vector_preview` 使用 cosine similarity 降序。
3. `hybrid` 对同一个 chunk 合并信号，标题/标签/摘要命中给予小幅 boost，最近更新只作为同分 tie-breaker。

## 5. 复杂文档解析增强

本阶段不追求完整 OCR，而是让复杂资料状态可解释、可筛选、可重试。

新增 parser status：

```ts
type KnowledgeParserStatus =
  | 'complete'
  | 'partial'
  | 'metadata_only'
  | 'requires_sidecar'
  | 'failed';
```

写入 `knowledge_sources.metadata` 和 `knowledge_extractions.metadata`：

```json
{
  "parser_status": "metadata_only",
  "parser_capabilities": ["metadata", "image_metadata"],
  "parser_warnings": ["OCR sidecar is not configured"],
  "requires_sidecar": true
}
```

解析策略：

- 文本、Markdown、JSON、YAML、CSV：`complete`，并补充结构化 metadata。
- CSV：生成 `table` metadata，包含列名、行数上限、样例行。
- JSON/YAML：生成 `layout` metadata，包含顶层 key 和节点数量上限。
- 图片：`metadata_only` 或 `requires_sidecar`，保留 mime、尺寸可用信息和 OCR 提示。
- PDF、Office：未配置 sidecar 时为 `requires_sidecar`，不伪装成解析完成。

## 6. Agent RAG 增强

Phase 2 只给普通 room chat 和 session agent 注入知识库工具。Phase 4A 放宽为：

- 非 internal message 的 room agent 均可注入知识库工具，包括 task、workflow、collaboration run。
- 保持系统上下文工具的旧限制，不把任务/workflow 系统查询能力一并放开。
- Agent env 增加 `OPENDEEPSEA_KNOWLEDGE_SEARCH_MODE=hybrid`。
- `openclaw:knowledge search` 增加 `--mode keyword|vector_preview|hybrid`，默认 `hybrid`。
- usage ref metadata 记录 `retrieval_mode`、`ranking_signals`、query 和命令来源。

Prompt 规则继续强调：

- 先检索再回答涉及项目资料、设计、验收、历史决策的问题。
- 回答中引用工具返回的 citation key。
- 不读取 SQLite、上传目录、本机绝对路径或未授权 workspace 文件。

本阶段不做“自动预检索并塞入 prompt”。`retrieval_context` 继续保留给后续阶段，避免错误召回污染任务执行。

## 7. 知识沉淀增强

新增治理视图和编辑能力：

### 7.1 治理信号

`knowledgeGovernanceService` 输出：

- duplicate：同项目同 `content_hash` 的多个 source。
- stale：source 标记 stale，或 metadata 中的 workspace path 已不存在。
- parser_incomplete：`parser_status` 为 `partial`、`metadata_only` 或 `requires_sidecar`。
- empty_index：ready 但 chunk_count 为 0。

新增 API：

```http
GET /api/knowledge/insights?projectId=<projectId>&roomId=<roomId>
```

响应包含聚合计数和每类前若干条 source id，用于页面提示和后续定位。

### 7.2 摘要、标签和事实编辑

扩展现有 `PATCH /api/knowledge/sources/:sourceId`：

```ts
{
  summary?: string | null;
  tags?: string[];
  metadataPatch?: {
    key_points?: string[];
    decisions?: string[];
    constraints?: string[];
    risks?: string[];
    learnings?: string[];
  };
}
```

编辑只更新派生知识，不改原始 extraction。所有数组字段限制数量和单项长度，避免 UI 和 prompt 失控。

## 8. 导入与知识源扩展

新增三个导入入口。

### 8.1 手动知识

```http
POST /api/projects/:projectId/knowledge/manual
```

请求：

```ts
{
  title: string;
  content: string;
  tags?: string[];
  roomId?: string;
}
```

创建 `source_type = manual`，正文进入 extraction 和 chunks，适合保存规范、结论、外部资料摘录。

### 8.2 URL/web 页面记录

```http
POST /api/projects/:projectId/knowledge/url
```

请求：

```ts
{
  url: string;
  title?: string;
  content?: string;
  tags?: string[];
  roomId?: string;
}
```

规则：

- URL 必须是 `http` 或 `https`。
- `content` 为空时创建 metadata-only source，状态为 `stale`，提示需要补充内容。
- `content` 非空时按用户提供内容入库，不主动联网抓取。
- metadata 记录 URL、host 和导入方式。

### 8.3 Workspace 文档

```http
POST /api/projects/:projectId/knowledge/workspace-docs
```

请求：

```ts
{
  paths: string[];
  roomId?: string;
  tags?: string[];
}
```

规则：

- 复用 `readWorkspaceFilePreview()`、路径归一化、忽略规则、二进制检测和大小限制。
- 每个路径创建或更新一个 `source_type = workspace_doc` 的 source。
- `source_id = workspace_doc:<relativePath>`，内容变化通过 `content_hash` 和 reprocess 判断。
- metadata 记录 relative path、language、truncated、content_hash。

## 9. 前端设计

`/knowledge` 保持高密度产品 UI，不新增营销式页面。

新增 UI：

1. 搜索区增加 segmented control：`关键词`、`向量预览`、`混合`。
2. 表格或移动卡片展示检索模式命中时的 score/ranking chips，默认只显示简短信号。
3. 工具栏增加导入菜单：`手动知识`、`URL`、`工作区文档`。
4. 顶部统计区增加治理提示：重复、解析不完整、空索引、过期。
5. 详情侧栏增加 `解析` 和 `治理` 小节，展示 parser status、warnings、ranking metadata 和可编辑事实字段。

交互约束：

- 导入表单使用现有 `Dialog`、`Input`、`Textarea`、`Button` 组件。
- 不做嵌套卡片。
- loading 使用按钮禁用和局部 skeleton，不用整页遮罩。
- 错误 toast 必须带具体原因，例如路径被忽略、URL 协议不支持、正文为空。

## 10. API 兼容

现有 API 保持可用：

- `GET /api/knowledge/search` 不传 `mode` 时仍返回 keyword 兼容结果。
- `PATCH /api/knowledge/sources/:sourceId` 保持现有 `status`、`enabled`、`tags`、`summary` 参数。
- 新增字段只作为可选字段返回，前端类型向后兼容。

新增或扩展：

```http
GET /api/knowledge/search?projectId=&q=&mode=keyword|vector_preview|hybrid
GET /api/knowledge/insights?projectId=&roomId=
POST /api/projects/:projectId/knowledge/manual
POST /api/projects/:projectId/knowledge/url
POST /api/projects/:projectId/knowledge/workspace-docs
```

CLI 扩展：

```bash
npm run openclaw:knowledge -- search --project <projectId> --query "<query>" --mode hybrid
```

## 11. 安全与错误处理

1. URL 导入不主动抓取远端，避免 SSRF。
2. Workspace 导入复用现有 workspace 文件安全边界，不允许绝对路径、路径逃逸、忽略文件、二进制和超限文件。
3. Embedding provider 不保存原始文件路径，只保存 chunk id、source id、project id、provider metadata 和向量 JSON。
4. Agent 工具输出不暴露 `storage_path`、SQLite 路径、上传目录或本机绝对路径。
5. 所有导入 API 校验 project/room 归属。
6. `metadataPatch` 限制数组长度、字符串长度和允许字段，不能任意覆盖系统 metadata。

## 12. 验收标准

1. `GET /api/knowledge/search?mode=hybrid` 能合并 FTS 和本地 vector preview 结果，并返回 citation 与 ranking signals。
2. chunk 创建或重建后能写入 `knowledge_chunk_embeddings`，删除 source/chunk 后 embedding 级联清理。
3. `openclaw:knowledge search --mode hybrid` 返回 hybrid 结果，并记录 retrieval mode usage metadata。
4. task/workflow/collaboration room agent prompt 能看到知识库工具说明，internal message 仍不注入。
5. 复杂文件在无法完整解析时显示 parser status 和 warnings，不再只有空 extraction。
6. 手动知识、URL/web、workspace doc 三类导入能创建 source、extraction、chunks，并可搜索命中。
7. 知识治理 API 能返回重复、解析不完整、空索引、过期聚合信息。
8. 前端 `/knowledge` 能切换检索模式、触发三类导入、展示治理提示和 parser/ranking 信息。
9. 相关后端测试、前端 API/页面测试和 `npm run build` 通过。

## 13. 风险与取舍

- `local-hash-v1` 不是语义 embedding：接受。它用于验证 provider、索引、hybrid 排序和 UI 流程，后续替换真实 provider。
- 向量 JSON 存 SQLite 会增加体积：256 维本地向量可控，后续真实 provider 可改为外部 vector id。
- hybrid 排序可能改变用户熟悉的 FTS 顺序：默认页面可保留关键词模式，Agent CLI 默认 hybrid。
- URL 不自动抓取会降低便利性：优先安全和本地可预测，后续单独设计受控 fetch。
- 复杂文档不直接 OCR 会留下能力缺口：先把状态、sidecar 边界和 UI 提示打通，避免不可见失败。

## 14. 分期关系

Phase 4A 完成后，后续可以拆分为：

1. Phase 4B：真实 embedding provider 配置、批量重建索引、外部 vector store 评估。
2. Phase 4C：Docling/Unstructured sidecar、OCR、PDF layout、Office 和表格结构化解析。
3. Phase 4D：自动 retrieval_context、GraphRAG/实体关系图谱和检索评测集。

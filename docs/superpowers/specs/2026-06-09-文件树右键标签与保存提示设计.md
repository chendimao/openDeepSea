# 文件树右键、标签页密度与保存提示设计

## 背景

会话页面的文件浏览器已经升级为可编辑工作台，但当前仍有三个局部体验问题：

- 文件树选中后右键没有稳定响应。
- 文件 tab 标签页视觉密度偏松，不够像代码编辑器。
- 文件保存成功后缺少明确反馈，用户只能通过工具栏状态判断。

本设计聚焦这三个问题，不改变后端 workspace API，不重做文件浏览器整体布局。

## 目标

- 文件树右键菜单在整行范围内稳定弹出，包括图标、文字、缩进、箭头附近和选中行空白区域。
- 保留现有文件树选中态、展开行为、新建、重命名、删除和复制路径能力。
- 文件 tab 更紧凑，减少高度、最小宽度、左右 padding、图标间距和标题最大宽度。
- 保存成功时使用已有 `sonner` toast 反馈，提示用户文件已保存。

## 非目标

- 不新增后端文件操作能力。
- 不改变 Monaco 编辑器能力、保存冲突弹窗或未保存确认流程。
- 不重做 Stitch 设计稿的整体高保真视觉，只处理本次反馈的局部问题。
- 不引入新的 toast 库或全局通知系统。

## 推荐方案

采用“文件树整行事件委托 + 紧凑 tab 样式 + 保存成功 toast”的组合方案。

文件树右键不再依赖标题文字节点的 `onContextMenu`。改为在文件树外层容器监听右键事件，并通过 DOM 向上解析当前行对应的文件或目录。标题节点继续携带 entry path/type 等数据，事件处理器从当前可见树数据中查找真实 entry，再打开现有右键菜单。

tab 样式只调整现有 FlexLayout 覆盖 CSS，不改变 tab 数据模型和拖拽排序逻辑。保存提示在 `FileBrowserWorkspace.saveFile()` 成功路径中调用 `toast.success()`，并使用文件相对路径作为 description。

## 备选方案与取舍

### 方案 A：整行事件委托

优点：

- 右键命中范围覆盖整行，能解决选中行空白区域右键无反应的问题。
- 对 `react-complex-tree` 内部渲染依赖较少。
- 改动范围集中在 `WorkspaceFileTree.tsx` 和少量 CSS。

缺点：

- 需要维护 DOM data attribute 与 visible tree item 的映射。

这是本次推荐方案。

### 方案 B：重写 react-complex-tree item renderer

优点：

- 从组件语义上把右键绑定到 row/item 容器。

缺点：

- 需要更大范围接管 tree item 渲染。
- 可能影响现有展开、聚焦、选择和键盘行为。
- 对这次局部修复来说成本偏高。

### 方案 C：只扩大标题节点 CSS 命中区

优点：

- 改动最小。

缺点：

- 仍可能无法覆盖目录箭头、缩进区域和某些选中行空白区域。
- 难以保证用户反馈的场景完全修复。

## 组件设计

### WorkspaceFileTree

- `WorkspaceTreeTitle` 保留图标、标题、active、selected、dirty、search match 等视觉职责。
- 标题节点增加稳定的 `data-entry-path`，用于右键事件委托解析。
- 外层 `.deepsea-workspace-tree` 增加 `onContextMenu`。
- 右键处理流程：
  - 阻止浏览器默认菜单。
  - 从事件目标向上查找最近的 entry 标记节点。
  - 根据 path 找到 `visibleTreeItems` 中的 entry。
  - 调用 `onSelectEntry(entry)` 同步选中状态。
  - 使用鼠标坐标打开现有 context menu。
- 如果没有解析到 entry，则不打开菜单，避免空白区域误触。

### WorkspaceFileTabs

组件逻辑不变，只通过 CSS 收紧密度：

- tabbar 高度调整为约 `30px` 到 `32px`。
- tab button 高度调整为约 `30px` 到 `32px`。
- tab 最小宽度调整为约 `108px` 到 `116px`。
- 左右 padding 调整为约 `10px` 到 `12px`。
- tab 图标尺寸和 gap 下调，dirty 标记保留。

### FileBrowserWorkspace

- 在保存成功并清理 dirty state 后调用 `toast.success('文件已保存', { description: path })`。
- 仅对真实保存动作提示；没有 dirty 内容时 `saveFile()` 直接返回，不弹 toast。
- 保存失败继续走现有 `saveError` 和冲突确认流程。

## 错误处理

- 右键无法解析到 entry 时不展示菜单。
- 保存失败不显示成功 toast。
- toast 调用不参与业务状态判断，不改变保存结果返回值。

## 验证方式

- 构建验证：`npm run build -w @openclaw-room/frontend`。
- 浏览器 smoke：
  - 打开会话文件浏览器页面。
  - 选择文件或目录后，在行内不同位置右键，菜单应稳定弹出。
  - 目录展开/折叠仍可用。
  - tab 标签页更紧凑，文件名、图标、关闭按钮和 dirty 标记不重叠。
  - 编辑文件后保存，右下角出现保存成功 toast。

## 验收标准

- 文件树选中行右键可稳定打开菜单。
- 文件树目录点击展开行为不回退。
- tab 标签页视觉密度明显收紧，仍保留可识别的选中态和 dirty 状态。
- 文件保存成功后通过 toast 明确提示。
- 前端构建通过。

## 风险

- `react-complex-tree` 生成的 DOM 结构可能变化，事件委托应尽量依赖自有 data attribute。
- tab 过度压缩可能导致长文件名和关闭按钮拥挤，需要在 smoke 截图中检查。
- 当前工作区存在其他未提交改动，提交时只应暂存本 spec 和本次实现相关文件。

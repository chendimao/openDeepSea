# 通用项目终端与 Skills 安全安装设计

## 背景

当前 `/skills` 页面已经能扫描本机 Codex、Claude Code、OpenCode 的原生 skills 目录，并以矩阵方式展示安装状态。用户希望后续能够在线安装 skills，同时安装过程可能包含交互，例如选择目标平台、选择全局或当前目录安装、确认覆盖等。

经过讨论，第一版不再优先实现多个远程 registry 的自定义下载和解压安装器，而是先提供一个可复用的项目终端能力。Skills 页面使用这个终端能力完成安装，但必须限制为 skills 安装相关安全命令，不能在 Skills 页面开放任意 shell。

本设计兼顾两个目标：

1. 建立一个后续可在项目调试、构建、Git 操作、workflow 接管等场景复用的通用项目终端底座。
2. 在 `/skills` 页面提供受限终端安装体验，让用户可以在页面内完成 `npx skills find`、`npx skills add` 等交互式安装流程。

## 目标

1. 提供可复用的前端终端组件，支持输出、输入、resize、终止和状态展示。
2. 提供后端 terminal session 管理能力，能启动真实 PTY 进程并通过 WebSocket 双向通信。
3. 支持两种终端 profile：
   - `project_shell`：完整项目 shell，供后续其他页面显式使用。
   - `skills_install`：Skills 页面专用受限终端，只允许执行 skills 安装相关安全命令。
4. Skills 页面通过 `skills_install` profile 安装 skills，安装完成或终端退出后自动刷新本地 skills matrix。
5. 保持当前本地 skills 扫描与 `$` planner skill picker 的行为不变。

## 非目标

1. 第一版不实现 skills.sh、AgentVerus、PolySkill、SkillsMP 等远程 registry 的统一下载器。
2. 第一版不自动解析网页搜索结果并静默安装。
3. 第一版不在 Skills 页面开放完整 shell。
4. 第一版不持久化完整终端日志。
5. 第一版不支持多人共享同一个终端会话。
6. 第一版不在终端中自动输入用户选择，也不尝试代替第三方安装器回答交互问题。

## 已确认产品决策

1. 底层能力需要支持完整 shell，后续可以在别的页面复用。
2. `/skills` 页面只使用受限安装终端。
3. Skills 安装过程中的交互直接在终端中完成。
4. 安装后以重新扫描本机 skills 目录作为结果确认来源。

## 用户体验

### Skills 页面

`/skills` 页面保留当前三平台矩阵。新增一个终端安装入口：

- 按钮文案：`终端安装 Skills`
- 打开后显示终端面板或抽屉。
- 顶部展示当前模式：`Skills 安装终端`
- 展示当前工作目录。
- 展示允许命令提示。
- 提供 `终止`、`关闭`、`刷新本地 Skills` 操作。

推荐初始提示：

```text
Skills 安装终端，只允许执行 skills 安装相关命令。
可用示例：
  npx skills find react
  npx skills add vercel-labs/skills/find-skills
  npx skills check
  npx skills update
```

用户输入命令后，如果命令符合允许规则，后端启动对应 PTY 子进程。安装器的后续交互输入直接传给运行中的 PTY。例如安装器询问平台、范围或覆盖策略时，用户直接在终端中回答。

命令完成后，终端回到受限提示符，并触发 `/api/platform-skills` 重新扫描。前端展示成功、失败或部分安装状态，实际结果以本地扫描为准。

### 后续通用项目终端

其他页面可以使用同一个 `TerminalPanel`，但通过 `project_shell` profile 启动完整 shell：

- 项目调试
- 构建和测试
- Git 操作
- workflow 失败后的人工接管
- agent 运行现场排查

这些入口必须显式标注为完整 shell，避免用户误以为它和 Skills 安装终端有相同限制。

## 架构

### 前端模块

新增可复用终端组件：

- `TerminalPanel`
- `TerminalDrawer`
- `useTerminalSession`

建议依赖：

- `@xterm/xterm`
- `@xterm/addon-fit`

组件职责：

1. 建立 WebSocket 连接。
2. 渲染终端输出。
3. 发送用户输入。
4. 发送终端 resize 事件。
5. 显示 session 状态、cwd、profile。
6. 提供终止和关闭操作。

Skills 页面只负责传入：

```ts
{
  profile: 'skills_install',
  projectId: selectedProjectId ?? null
}
```

未来项目页或调试页可以传入：

```ts
{
  profile: 'project_shell',
  projectId
}
```

### 后端模块

新增 `terminal` 子系统：

- `terminal/types.ts`
- `terminal/service.ts`
- `terminal/restricted-skills-shell.ts`
- `terminal/routes.ts`
- `terminal/socket-controller.ts`

后端职责：

1. 创建 terminal session。
2. 根据 profile 选择启动完整 shell 或受限安装终端。
3. 管理 PTY 生命周期。
4. 接收 WebSocket 输入并写入 PTY。
5. 推送输出、状态、退出事件。
6. 处理 resize、kill、idle timeout。
7. 终端结束后触发 Skills 扫描刷新通知。

建议依赖：

- `node-pty`

## API 设计

### 创建终端会话

```http
POST /api/terminals
```

请求：

```json
{
  "profile": "skills_install",
  "projectId": "project-id-or-null",
  "cols": 120,
  "rows": 32
}
```

响应：

```json
{
  "id": "terminal-session-id",
  "profile": "skills_install",
  "cwd": "/path/to/project",
  "status": "running"
}
```

### 查询终端状态

```http
GET /api/terminals/:id
```

响应：

```json
{
  "id": "terminal-session-id",
  "profile": "skills_install",
  "cwd": "/path/to/project",
  "status": "running",
  "startedAt": 1780900000000,
  "endedAt": null,
  "exitCode": null
}
```

### 终止终端

```http
POST /api/terminals/:id/kill
```

响应：

```json
{
  "ok": true
}
```

### WebSocket 事件

复用现有 `/ws` 入口，新增 terminal 事件类型。

客户端事件：

```ts
type TerminalClientEvent =
  | { type: 'terminal:subscribe'; sessionId: string }
  | { type: 'terminal:unsubscribe'; sessionId: string }
  | { type: 'terminal:input'; sessionId: string; data: string }
  | { type: 'terminal:resize'; sessionId: string; cols: number; rows: number }
  | { type: 'terminal:kill'; sessionId: string };
```

服务端事件：

```ts
type TerminalServerEvent =
  | { type: 'terminal:ready'; sessionId: string; cwd: string; profile: TerminalProfile }
  | { type: 'terminal:output'; sessionId: string; data: string }
  | { type: 'terminal:status'; sessionId: string; status: TerminalStatus }
  | { type: 'terminal:exit'; sessionId: string; exitCode: number | null; signal: string | null }
  | { type: 'platform_skills:refresh_requested' };
```

`platform_skills:refresh_requested` 只作为前端刷新提示，不替代前端主动 refetch。

## Profile 行为

### project_shell

`project_shell` 是完整 shell profile。

启动规则：

1. shell 使用 `process.env.SHELL`。
2. 如果没有 `SHELL`，按平台 fallback 到 `zsh`、`bash` 或 `sh`。
3. cwd 优先使用项目路径。
4. 无项目时使用 OpenDeepSea 启动 cwd。

限制：

1. 必须通过 local access token。
2. UI 必须明确标注这是完整 shell。
3. 默认不在 Skills 页面暴露。

### skills_install

`skills_install` 是受限安装 profile。它使用同一个终端 UI，但后端不直接启动用户 shell，而是启动一个受限命令解释器。

行为：

1. 空闲状态显示受限提示符。
2. 用户输入一行命令后，后端解析命令。
3. 命令符合 allowlist 时，使用 PTY 启动对应安装命令。
4. 子进程运行期间，所有输入原样转发给子进程，用于响应交互式安装器。
5. 子进程退出后，回到受限提示符。
6. 输入不符合 allowlist 时，终端输出拒绝原因，不执行命令。

允许命令范围：

```text
npx skills find ...
npx skills add ...
npx skills check
npx skills update
npx --yes skills find ...
npx --yes skills add ...
npx --yes skills check
npx --yes skills update
skills find ...
skills add ...
skills check
skills update
clear
exit
pwd
```

禁止规则：

1. 禁止 shell 连接符：`;`、`&&`、`||`、`|`。
2. 禁止重定向：`>`、`>>`、`<`。
3. 禁止命令替换：`` `...` ``、`$(...)`。
4. 禁止环境变量前缀执行：`FOO=bar npx ...`。
5. 禁止任意非 allowlist 可执行文件。

命令启动必须避免 `shell: true`，使用解析后的 executable 和 argv 启动 PTY。

## 安全设计

### 访问控制

所有 terminal HTTP 和 WebSocket 操作都必须通过现有 local access token 机制。没有 local access 权限时不能创建、订阅、输入或终止终端。

### 会话隔离

1. 每个 terminal session 有独立 id。
2. WebSocket 只能订阅已创建且存在的 session。
3. 关闭浏览器连接不立即杀死 session，但 session 会进入 idle 计时。
4. 超过 idle timeout 后自动终止。

建议默认：

- `skills_install` idle timeout：10 分钟
- `project_shell` idle timeout：30 分钟

### 环境变量

默认继承最小环境变量：

- `HOME`
- `PATH`
- `SHELL`
- `TERM`
- `LANG`
- `LC_ALL`
- npm 运行所需基础变量

默认不主动注入 API key。若进程继承了 OpenDeepSea 自身环境，必须过滤常见敏感变量：

- 包含 `TOKEN`
- 包含 `SECRET`
- 包含 `API_KEY`
- 包含 `PASSWORD`
- 包含 `PRIVATE_KEY`

如后续确需完整环境，可在 `project_shell` 入口单独提供显式开关，不影响 Skills 页面。

### 日志

第一版不持久化完整终端输出。只记录内存状态和极简审计信息：

- session id
- profile
- cwd
- startedAt
- endedAt
- exitCode
- killedByUser

Skills 页面可以在运行中展示完整输出，但页面刷新后不恢复历史输出。

### 进程回收

1. 用户点击终止时，后端先发送 SIGTERM。
2. 超时未退出时发送 SIGKILL。
3. 后端退出时统一终止所有 terminal sessions。
4. session 结束后从 session manager 中移除或保留短时状态。

## Skills 页面安装结果确认

终端安装命令的输出不作为唯一事实来源。安装完成后，前端执行以下动作：

1. refetch `api.listPlatformSkillSummaries`
2. refetch `api.listPlatformSkillAggregates`
3. 根据本地扫描结果更新矩阵和详情面板

如果安装器输出成功，但本地扫描没有新增 skill，页面仍应以扫描结果为准，并提示用户检查终端输出。

## 错误处理

### 后端错误

- `401/403`：无 local access 权限。
- `404`：session 不存在或已结束。
- `400`：profile、rows、cols 或 projectId 无效。
- `409`：session 状态不允许当前操作。
- `500`：PTY 启动失败。

### 前端状态

终端组件至少展示：

- `connecting`
- `running`
- `exited`
- `failed`
- `killed`
- `idle-timeout`

Skills 页面在 `failed` 或 `exited` 后仍允许刷新本地 matrix。

## 测试策略

### 后端单元测试

1. `skills_install` 拒绝非 allowlist 命令。
2. `skills_install` 拒绝 shell 连接符、重定向和命令替换。
3. `skills_install` 允许 `npx skills find`、`npx skills add`、`skills check`。
4. session kill 会终止 PTY 并发送 exit 事件。
5. resize 会调用 PTY resize。
6. terminal routes 需要 local access。

### 前端测试

1. `TerminalPanel` 能渲染输出事件。
2. 用户输入会发送 `terminal:input`。
3. resize 会发送 `terminal:resize`。
4. Skills 页面使用 `skills_install` profile，不使用 `project_shell`。
5. 终端退出后触发本地 skills refetch。

### 最低验证

第一版完成后至少运行：

```bash
npm run build
cd packages/backend && node --import tsx --test src/terminal/*.test.ts src/platform-skills/*.test.ts
```

如果新增前端测试 runner，则补充对应前端测试命令；否则以 `npm run build` 和浏览器 smoke 验证为最低门禁。

## 迁移与兼容

1. 不改变现有 `/api/platform-skills` 扫描接口。
2. 不改变现有 Skills 页面 matrix 数据结构。
3. 不改变会话输入框 `$skill` picker 行为。
4. 新增 terminal WebSocket 事件需要扩展 `WsClientEvent` 和 `WsServerEvent` union，但不影响现有事件。
5. `node-pty` 是 native dependency，需要在安装和构建文档中记录平台依赖风险。

## 分阶段实施

### 第一阶段：终端底座

实现 terminal session manager、routes、WebSocket 事件和基础 `TerminalPanel`。

### 第二阶段：Skills 受限安装终端

实现 `skills_install` 受限命令解释器，并接入 `/skills` 页面。

### 第三阶段：通用项目终端入口

在项目相关页面提供 `project_shell` 入口。这个阶段需要单独确认入口位置、可见性和权限提示。

## 验收标准

1. `/skills` 页面可以打开 Skills 安装终端。
2. Skills 安装终端不能执行任意 shell 命令。
3. Skills 安装终端可以执行 `npx skills find` 和 `npx skills add`，并能响应安装器交互。
4. 终端退出后本地 skills matrix 自动刷新。
5. 后端能终止 terminal session，且不会遗留运行中的 PTY。
6. 通用 `project_shell` profile 已在后端能力层存在，但不在 `/skills` 页面暴露。
7. 所有新增 terminal API 和 WebSocket 操作都需要 local access。

# 跨项目活跃会话面板设计

## 背景

当前会话工作台左侧使用“会话历史”语义，主要展示当前项目下的 `history_records`。这个模型隐含了两个不准确前提：

1. 左侧列表展示的是已经结束或归档的会话。
2. 当前工作台只有一个需要关注的 active session。

新的目标是支持多项目、多会话同步开发。会话不一定已经结束，也不一定只属于当前项目。多个会话可以同时运行，彼此互不影响。用户需要一个全局入口快速查看、切换和管理这些仍在工作台中的会话。

## 目标

- 将左侧从“会话历史”重新定义为“活跃会话”。
- 展示任意项目下所有未被用户手动关闭的会话。
- 点击左侧会话只切换主视图焦点，不暂停、不归档、不替换其他会话。
- 支持多个会话同时运行，并在左侧看到轻量状态变化。
- 保留单物理 WebSocket 连接，但调整为全局活跃会话订阅加当前焦点会话详情订阅。
- 将 `history_records` 降级为归档摘要、恢复依据和交接材料，不再作为左侧主列表数据源。

## 非目标

- 不在本阶段实现完整多面板并排查看多个会话详情。
- 不为每个会话创建独立 WebSocket 连接。
- 不将所有归档会话默认塞回左侧列表。
- 不改变底层 ACP provider 的运行协议。
- 不在切换会话时隐式执行 resume、fork、archive 或 compact。

## 核心概念

### Session

`session` 是一条独立时间线，包含用户消息、智能体运行、证据、上下文、计划和状态。它可以正在运行、暂停、阻塞、失败、完成或归档。

### 活跃会话

活跃会话是“用户仍希望在左侧工作台中保留关注入口”的 session。它不等同于运行中，也不等同于数据库中的 `status = active`。

规则：

- 只要用户没有手动关闭，会话就留在左侧。
- 会话当前没有运行，也可以是活跃会话。
- 会话失败、阻塞、暂停后仍应留在左侧，方便用户处理。
- 用户执行关闭或归档后，该会话从左侧移出。

### 历史记录

`history_records` 是已归档阶段的摘要和恢复材料，不再是左侧主列表。它用于：

- 从归档摘要恢复新会话。
- 查看已结束阶段的 resume brief。
- 导出或追溯已经关闭的工作。

## 左侧信息架构

左侧标题使用“活跃会话”。

推荐结构：

```text
活跃会话

置顶
- Project A / 实现文件引用 / running
- Project B / 修复构建失败 / blocked

最近活跃
- Project C / 设计登录流程 / active
- Project A / 接入真实数据 / paused
```

每条会话展示：

- 项目名。
- 会话标题。
- 状态：running、active、paused、blocked、failed、completed。
- 最近更新时间。
- 当前运行 agent/model，或最近一条事件摘要。
- 是否有未读事件。
- 是否置顶。

每条会话支持操作：

- 切换：点击 item，导航到对应 session。
- 置顶 / 取消置顶。
- 暂停 / 取消 / 继续运行中的 run。
- 分叉。
- 关闭：从活跃会话面板移出。

关闭操作必须显式触发，不能由 `/new`、切换项目或切换 session 自动触发。

## 排序与过滤

默认排序：

1. 置顶会话在前。
2. 运行中会话优先。
3. 有未读事件的会话优先。
4. 最近更新时间倒序。

推荐过滤：

- 项目。
- 状态。
- Provider / model。
- 搜索标题、项目名和最近摘要。

归档或已关闭会话不进入默认列表，可通过单独的“已关闭 / 归档”入口查看。

## 路由与切换语义

点击左侧会话导航到：

```text
/projects/:projectId/sessions/:sessionId
```

切换行为：

- 只改变主视图焦点。
- 不改变目标会话运行状态。
- 不改变原会话运行状态。
- 不创建新会话。
- 不生成 history record。
- 不归档当前会话。

如果目标会话来自另一个项目，主视图应同时切换项目上下文。

## 命令语义

`/new`：

- 创建一条新的会话时间线。
- 不归档当前会话。
- 不把当前会话从左侧移除。
- 创建成功后可自动切换焦点到新会话。

`/close` 或显式关闭按钮：

- 将会话从活跃会话面板移除。
- 可选择同步生成 `history_record` 作为交接摘要。
- 不删除原始 session 数据。

`/archive`：

- 关闭会话并标记为归档。
- 生成或更新归档摘要。

`/resume <historyRecordId>`：

- 从归档摘要创建新会话时间线。
- 新会话进入活跃会话面板。

`/fork`：

- 从当前会话或历史记录创建分支会话时间线。
- 新会话进入活跃会话面板。

## 数据模型

建议新增字段：

```ts
type Session = {
  closed_at: number | null;
  pinned_at: number | null;
  last_viewed_at: number | null;
};
```

字段语义：

- `closed_at = null` 表示仍展示在活跃会话面板。
- `closed_at != null` 表示用户已关闭，不再默认展示。
- `pinned_at != null` 表示置顶，值越新排序越靠前。
- `last_viewed_at` 用于未读状态和切换体验。

执行状态仍保留在现有 `status`、`phase` 和 run 状态中。不要用 `status` 单独决定是否展示在左侧，因为“用户是否仍关注”和“会话是否正在执行”是两个不同维度。

活跃会话查询条件：

```sql
WHERE closed_at IS NULL
ORDER BY pinned_at DESC NULLS LAST, updated_at DESC
```

如 SQLite 排序兼容性需要，可使用表达式：

```sql
ORDER BY pinned_at IS NULL, pinned_at DESC, updated_at DESC
```

## API 设计

新增或扩展接口：

```text
GET /api/active-sessions
GET /api/projects/:projectId/sessions?scope=active
PATCH /api/sessions/:sessionId
POST /api/sessions/:sessionId/close
POST /api/sessions/:sessionId/pin
POST /api/sessions/:sessionId/unpin
```

`GET /api/active-sessions` 返回跨项目轻量列表，不返回完整 transcript：

```ts
type ActiveSessionSummary = {
  id: string;
  project_id: string;
  project_name: string;
  project_path: string;
  title: string;
  status: SessionStatus;
  phase: SessionPhase;
  provider: AcpBackend | null;
  model: string | null;
  pinned_at: number | null;
  updated_at: number;
  unread_count: number;
  active_run_count: number;
  latest_event_summary: string | null;
};
```

## WebSocket 设计

保留一个物理 WebSocket 连接。

新增客户端事件：

```ts
type WsClientEvent =
  | { type: 'active_sessions:subscribe' }
  | { type: 'active_sessions:unsubscribe' }
  | { type: 'session:subscribe'; sessionId: string }
  | { type: 'session:unsubscribe'; sessionId: string };
```

新增服务端事件：

```ts
type WsServerEvent =
  | { type: 'active_sessions:snapshot'; sessions: ActiveSessionSummary[] }
  | { type: 'active_session:upsert'; session: ActiveSessionSummary }
  | { type: 'active_session:remove'; sessionId: string }
  | { type: 'session_workspace:snapshot'; projectId: string; sessionId: string; payload: SessionWorkspacePayload };
```

订阅模型：

- 左侧订阅 `active_sessions`，接收跨项目轻量列表。
- 主视图订阅当前焦点 `sessionId`，接收完整 transcript、run、evidence、context 等事件。
- 非当前会话不订阅完整详情流，只接收活跃列表轻量更新。

这个模型可以继续使用单 WebSocket，避免每个会话一个连接带来的重连、资源和清理复杂度。

## 前端组件边界

建议将现有左侧历史组件替换为：

```text
ActiveSessionsRail
```

职责：

- 渲染跨项目活跃会话列表。
- 管理搜索、过滤、置顶和关闭操作。
- 处理点击切换路由。
- 展示轻量运行状态。

工作台页面职责：

- 根据 URL 中的 `projectId/sessionId` 请求当前会话 workspace snapshot。
- 只订阅当前焦点 session 的详情流。
- 对活跃会话列表事件只更新左侧，不污染当前详情 payload。

## 后端边界

建议新增 active session view model：

```text
session-active-view-model.ts
```

职责：

- 聚合 session、project、latest run、latest event。
- 生成 `ActiveSessionSummary`。
- 提供跨项目排序。

`history_records` 相关逻辑保留在归档、resume 和 export 路径中，不再驱动左侧主列表。

## 迁移策略

1. 新增 `closed_at`、`pinned_at`、`last_viewed_at` 字段，默认 `NULL`。
2. 现有非归档 session 默认进入活跃会话面板。
3. 现有 `history_records` 保持不变，不迁移成活跃会话。
4. `/new` 行为改为创建新 session，不再自动归档旧 session。
5. 增加显式关闭或归档入口，让用户主动移出左侧。

## 测试与验证

后端验证：

- 创建多个项目和多个 session，`GET /api/active-sessions` 返回跨项目列表。
- `closed_at = null` 的 session 出现在列表中。
- 设置 `closed_at` 后，该 session 从列表移除。
- `pinned_at` 会影响排序。
- `/new` 不归档当前 session。
- `resume` 和 `fork` 创建的新 session 会进入活跃列表。

WebSocket 验证：

- 一个连接可同时订阅 `active_sessions` 和当前 `session`。
- 当前 session 的完整流不广播给只订阅活跃列表的客户端。
- 非当前 session 运行状态变化会更新左侧摘要。
- 关闭 session 后广播 `active_session:remove`。

前端验证：

- 左侧显示跨项目活跃会话。
- 点击另一个项目的 session 后，URL 和主视图同步切换。
- 切换焦点不暂停当前运行中的其他 session。
- `/new` 创建新会话后，旧会话仍保留在左侧。
- 关闭会话后从左侧移除，但详情数据仍可通过归档入口访问。

## 风险与权衡

- 活跃会话列表如果订阅完整 session 流会导致前端事件压力过大，因此必须区分轻量摘要和详情流。
- 如果只用现有 `status` 决定是否显示，会混淆“执行状态”和“用户工作台状态”，后续会很难维护。
- 跨项目列表会让导航和权限边界更敏感，所有 session 查询必须校验项目存在和本地访问规则。
- 归档摘要和活跃会话并存期间，UI 文案必须避免继续使用“历史”指代左侧主列表。

## 验收标准

- 左侧主列表命名为“活跃会话”。
- 左侧数据源来自 sessions，不来自 history_records。
- 未手动关闭的任意项目 session 都可以出现在左侧。
- 多个 session 可同时运行，切换焦点不互相影响。
- 单物理 WebSocket 继续保留，并支持活跃列表订阅与当前详情订阅分离。
- `/new` 不再隐式归档当前会话。
- 关闭或归档是显式动作。

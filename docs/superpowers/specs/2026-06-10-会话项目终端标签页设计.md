# 会话项目终端标签页设计

## 背景

会话页面的中间工作区已经通过 `flexlayout-react` 固定提供「对话记录」和「文件浏览器」两个标签页。文件浏览器支持在当前项目目录中浏览、打开、编辑、保存、创建、重命名和删除文件。Skills 页面已经存在基于 `TerminalPanel` 的模拟终端体验，后端也已经提供 `project_shell` 和 `skills_install` 两类 terminal profile。

本设计在会话中间工作区新增一个固定标签页「项目终端」，位于「文件浏览器」右侧，复用现有模拟终端能力，并让终端默认运行在当前项目目录。

## 目标

- 在会话中间工作区固定展示第三个标签页：「项目终端」。
- 第一次切到「项目终端」时懒启动 shell，初始进入会话页不自动启动 shell。
- 在「对话记录」「文件浏览器」「项目终端」之间切换时保持同一个前端终端实例和 shell 会话。
- 终端默认工作目录为当前项目路径。
- 终端权限继承当前本机用户 shell 权限，不额外限制访问项目目录外文件。
- 终端视觉和交互参考 Skills 页面模拟终端，复用现有 xterm、状态、终止、resize、WebSocket 输入输出能力。

## 非目标

- 不新增目录沙盒或命令白名单。
- 不新增后端 terminal API。
- 不改变 Skills 页 `skills_install` 受限终端行为。
- 不把终端放进文件浏览器内部 split，也不放进右侧 inspector。
- 不在会话页初始加载时自动创建 shell 进程。

## 已确认方案

采用固定中间标签页方案：

`对话记录` / `文件浏览器` / `项目终端`

该方案最符合“文件浏览器右边再固定一个标签页”的需求。它把终端和文件浏览器作为同级工作面板，不挤占文件编辑器，也不占用右侧 inspector 的会话状态、证据和 diff 空间。

备选方案已经排除：

- 文件浏览器内部 split：可以同时看文件和终端，但会压缩编辑器并扩大文件浏览器职责。
- 右侧 inspector 终端：可以边看对话边执行命令，但会和会话状态、证据、diff 竞争空间。

## 前端设计

### `SessionCenterWorkspace`

`SessionCenterWorkspacePane` 增加：

```ts
type SessionCenterWorkspacePane = 'transcript' | 'file-browser' | 'project-terminal';
```

FlexLayout model 增加固定 tab：

- id: `session-project-terminal-tab`
- name: `项目终端`
- component: `project-terminal`
- 不允许关闭、拖拽、重命名和移动，保持与现有两个固定 tab 一致。

factory 处理新增 component：

- `transcript`：继续渲染传入的对话记录节点。
- `file-browser`：继续渲染 `FileBrowserWorkspace`。
- `project-terminal`：渲染会话页专用项目终端容器，内部复用 `TerminalPanel`。

SSR fallback 的 tab 文案补充「项目终端」。SSR 环境仍只渲染 transcript，避免服务端初始化 xterm。

### 项目终端容器

新增轻量组件或内联 wrapper，职责只包括把 `TerminalPanel` 接入会话页：

```tsx
<TerminalPanel
  profile="project_shell"
  projectId={projectId}
  title="项目终端"
  className="deepsea-project-terminal-panel"
/>
```

该 wrapper 不新增终端状态机，不直接处理 WebSocket，不复制 Skills 页逻辑。

样式要求：

- 终端填满 FlexLayout tab 内容区。
- 避免和中间工作区容器产生重复圆角、重复阴影或多层卡片感。
- xterm 内容区保持稳定高度，tab 切换和 resize 不应导致布局抖动。

### `SessionShellView`

`onActivePaneChange` 继续接收当前 pane。

`isSessionInspectorVisibleForWorkspacePane` 保持：

```ts
return pane === 'transcript';
```

因此切到「文件浏览器」或「项目终端」时，右侧 inspector 隐藏，中间区使用 `deepsea-main--without-inspector` 的两列布局。

## 后端设计

复用现有 terminal 后端：

- `POST /api/terminals`
- `profile: 'project_shell'`
- `projectId`
- `terminal:*` WebSocket 事件

`project_shell` 已有行为：

- 如果传入 `projectId`，通过 `projectRepo.get(projectId)` 查找项目。
- `cwd` 使用项目路径。
- 使用 `$SHELL` 或 `/bin/zsh` 启动真实 shell。
- 环境变量继承当前服务端进程环境，并设置 `TERM=xterm-256color`、`FORCE_COLOR=1`。

如果项目不存在，现有 API 返回错误即可，不新增特殊分支。

## 生命周期

- 初始进入会话页：不创建 terminal session。
- 第一次打开「项目终端」tab：`TerminalPanel` mount，并调用 `createTerminalSession`。
- tab 切换期间：FlexLayout 保持 tab 内容，终端实例和 shell 会话持续存在。
- 终端退出或点击终止：复用现有状态和退出提示。
- 会话页卸载：前端取消 terminal 订阅并释放 xterm；后端 shell 仍由终止按钮、进程退出或既有 idle timeout 收尾。

## 错误处理

- 创建 terminal session 失败：复用 `TerminalPanel` 的错误状态和 xterm 输出。
- 项目不存在：后端返回 404，前端显示错误信息。
- WebSocket 输入输出失败：复用现有 `TerminalPanel` 错误路径。
- shell 退出、被 kill、idle timeout：复用现有状态 chip 和退出消息。

## 验证计划

前端定向测试：

- `SessionCenterWorkspace` SSR markup 包含「项目终端」。
- `getSessionCenterWorkspacePaneForTabId('session-project-terminal-tab')` 返回 `'project-terminal'`。
- 测试或源码断言覆盖 `TerminalPanel` 以 `profile="project_shell"` 和 `projectId` 接入会话页。

后端定向测试：

- 创建 `project_shell` terminal 并传入 `projectId` 时，返回的 `cwd` 等于项目路径。

最低验证门禁：

- 前端相关测试。
- 后端 terminal 相关测试。
- `npm run build`。

## 风险与约束

- 该终端拥有本机用户 shell 权限，只是默认目录为当前项目路径。用户可以通过普通 shell 命令访问项目外文件。
- 如果 FlexLayout 实际 unmount 非激活 tab，需要在实现阶段调整为保持 tab 内容或在会话页外层持有 terminal 实例；验收标准仍是 tab 切换期间保持同一个 shell 会话。
- 当前工作区已有多处未提交改动，实现时必须避免覆盖非本任务改动。

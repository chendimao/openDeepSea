# Electron 数据目录设置与清除数据设计

## 背景

Electron 版当前在 main 进程启动 backend sidecar 时，将 `OPENDEEPSEA_DATA_DIR` 与 `OPENCLAW_ROOM_DB` 指向 Electron `userData/data`。用户需要在设置中修改桌面数据目录，并能清除本地数据。数据目录不能存入 SQLite，因为 SQLite 文件本身位于该目录内。

## 目标

- Electron 版系统设置显示“桌面数据”区块。
- 用户可以查看当前数据目录、默认目录、待生效目录。
- 用户可以选择新的数据目录；目录变更保存到 Electron 独立 JSON 配置，重启后生效。
- 用户可以清除当前 Electron 数据目录里的 OpenDeepSea 数据；清除后重启应用。
- Web 端与未来远程 Web 模式不暴露本机数据目录与清除数据能力。

## 非目标

- 不做旧数据自动迁移。
- 不清除用户项目源码目录。
- 不通过后端 HTTP API 暴露清除本机数据能力。
- 不清除 Electron logs、应用配置文件本身或非数据目录内容。

## 架构

Electron main 进程新增桌面数据目录配置模块。模块负责：

- 从 `app.getPath('userData')/desktop-settings.json` 读取配置。
- 计算默认目录 `app.getPath('userData')/data`。
- 验证自定义目录路径，禁止空路径、相对路径、根目录、home 目录和当前应用配置目录。
- 在数据目录内写入 marker 文件 `.opendeepsea-data-dir.json`。
- 只有 marker 匹配时才允许清除目录内容。

Preload 通过 `contextBridge` 暴露 `window.openDeepSeaDesktop`：

- `getDataDirectory()`
- `chooseDataDirectory()`
- `resetDataDirectory()`
- `clearData()`
- `restartApp()`

前端系统设置页只在该 API 存在时显示“桌面数据”区块。目录变更后显示“重启后生效”，用户可立即重启。清除数据按钮触发二次确认，再调用 Electron API。

## 数据流

1. Electron 启动时读取 desktop settings，计算 active data dir。
2. main 进程用 active data dir 注入 backend 环境变量。
3. 设置页打开时通过 preload 查询当前目录状态。
4. 选择目录后 main 进程保存 pending data dir，并返回状态。
5. 重启后 active data dir 切换到新目录。
6. 清除数据时 main 进程停止 backend，校验 marker，删除数据目录内容，重新创建 marker，然后重启应用。

## 安全策略

- 清除数据只在 Electron main 进程执行，不经后端 HTTP。
- 清除前必须用户确认。
- 目录内必须存在 OpenDeepSea marker；没有 marker 不删除。
- 默认目录首次使用会自动创建 marker。
- 自定义目录保存后也会创建 marker，便于后续清除。
- 清除目录内容时保留 marker 文件本身，避免误删整目录。

## UI 设计

“桌面数据”作为系统设置常规类目下的一个紧凑设置区块，沿用现有设置页控件风格：

- 显示当前数据目录，使用等宽字体和截断。
- 显示默认数据目录和 pending 目录。
- 操作按钮：选择数据目录、恢复默认目录、重启应用、清除数据。
- 清除数据按钮使用 danger 样式，文案明确为“清除桌面数据”。
- 非 Electron 运行时不显示该区块。

## 验收标准

- Electron dev/prod 启动 backend 时使用配置后的数据目录。
- 修改目录不立即切换当前 backend，界面明确提示重启后生效。
- 清除数据会停止 sidecar、删除当前数据目录内容、重新创建 marker 并重启。
- 无 marker 的目录不会被清除。
- Web 端没有 `window.openDeepSeaDesktop` 时，设置页不显示桌面数据区块。
- 相关单元测试、前端测试、桌面构建和打包 smoke 通过。

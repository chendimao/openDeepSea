# 全局会话提示词注入与旧群聊前端收敛设计

## 背景

系统设置需要新增一个全局提示词注入界面。用户可以输入需要全局注入的提示词，并要求它在项目会话聊天中具备最高优先级。当前目标会话入口是 Session Workspace，例如 `/projects/:projectId/sessions/:sessionId`。

旧房间群聊已经不再作为主要使用路径。清理范围采用“前端收敛、后端兼容保留”：移除或弱化旧群聊的用户可见入口与前端概念，但暂不删除后端 `rooms/messages` 数据结构、API、dispatcher 或数据库表，避免破坏资源库、workflow、历史来源和兼容数据。

## 目标

1. 在系统设置中新增“全局会话提示词”配置界面。
2. 保存一个系统级 `global_session_prompt`，用于所有 Session Workspace 会话聊天。
3. 在会话消息运行前，把全局提示词注入到 session runtime prompt 最前面。
4. 保持用户原始输入、文件引用、Context Inspector 和显式 `$skill` 语义不变。
5. 收敛旧房间群聊前端暴露面，让“会话”成为主入口。

## 非目标

- 不覆盖旧房间群聊运行链路。
- 不覆盖全局聊天 `/chat` 的纯模型调用。
- 不删除后端 room/message 表、API 或历史数据。
- 不做破坏性迁移。
- 不把 `global_session_prompt` 当作 secret 管理。

## 用户可见行为

系统设置弹窗新增一个独立分类，名称为“会话提示词”。该分类内提供一个多行文本框：

- 标题：全局会话提示词
- 描述：会在每次项目会话聊天运行前注入，优先级高于上下文、文件引用和用户输入。
- 支持较长输入，并显示字符计数，例如 `0 / 12000`。
- 为空时显示“未启用全局注入”的轻量提示。
- 保存继续使用系统设置弹窗右下角的“保存系统设置”。

用户在 Session Workspace 输入框发送的内容保持原样展示和存储。注入只发生在后端调用 ACP provider 前的 runtime prompt 拼接阶段。

## 数据模型

在现有 `settings` 表 system row 中新增可空字段：

```ts
global_session_prompt: string | null
```

字段规则：

- 仅 system scope 生效。
- 不做 project/room 继承。
- 前后空白 trim。
- 空字符串保存为 `null`。
- 最大长度为 `12000` 字符，避免一次配置让所有 session prompt 过长。
- 通过系统设置接口正常返回，不做密钥脱敏。

## API 设计

沿用现有系统设置接口。

`GET /api/settings/system` 返回：

```ts
{
  global_session_prompt: string | null
}
```

`PATCH /api/settings/system` 接收：

```ts
{
  global_session_prompt?: string | null
}
```

后端校验：

- `undefined` 表示不修改。
- `null` 或 trim 后为空表示清空。
- 超过最大长度返回 `400`。

## Prompt 注入顺序

全局会话提示词在 Session Workspace runtime prompt 中位于最前面。推荐最终结构：

```md
## Global Session Instruction
<系统设置中配置的全局会话提示词>

本轮 prompt 来源由 SessionOS Context Inspector 记录。

当前目标：...

## Context Sources
...

## Referenced Files
...

## Explicit Platform Skills
...

## User Request
<用户原始输入>
```

为空时不插入 `Global Session Instruction` 块。

该优先级只表示 OpenDeepSea 自己生成的 session runtime prompt 内部优先级最高；它不覆盖系统、开发者、平台安全策略或 provider 原生更高层指令。

## 后端改动点

主要链路：

- `packages/backend/src/db.ts`：为 `settings` 增加 `global_session_prompt` 列迁移。
- `packages/backend/src/types.ts`：扩展 `SystemSettings` 类型。
- `packages/backend/src/repos/settings.ts`：读取、规范化、保存 `global_session_prompt`。
- `packages/backend/src/routes.ts`：系统设置 PATCH schema 增加字段与长度校验。
- `packages/backend/src/session-message-dispatch.ts`：在 `buildRuntimePrompt()` 或调用前读取系统设置，并把注入块放在最前面。

优先把注入逻辑集中成小函数，例如：

```ts
function buildGlobalSessionInstructionBlock(prompt: string | null): string {
  const trimmed = prompt?.trim();
  return trimmed ? `## Global Session Instruction\n${trimmed}` : '';
}
```

`dispatchSessionUserMessage()` 是用户会话消息的入口。注入放在这里可以只覆盖用户确认的 Session Workspace 会话聊天，不会污染旧群聊、全局聊天或模型测试。

## 前端改动点

主要链路：

- `packages/frontend/src/lib/types.ts`：扩展 `SystemSettings`。
- `packages/frontend/src/lib/api.ts`：`updateSystemSettings()` 增加 `global_session_prompt`。
- `packages/frontend/src/components/SettingsDialogs.tsx`：系统设置分类增加 `sessionPrompt`，新增多行文本框和字符计数。
- `packages/frontend/src/lib/i18n.tsx`：补充中英文文案。

`SystemSettingsCategory` 从：

```ts
'general' | 'chat' | 'model'
```

扩展为：

```ts
'general' | 'sessionPrompt' | 'chat' | 'model'
```

新增分类不放进“聊天协作默认值”，避免与旧房间群聊设置混淆。

## 旧群聊前端收敛

采用 B 方案：

- 保留顶部“会话”为主入口。
- `/chat` 当前是全局聊天，不等同旧房间群聊，本轮不删除。
- 项目卡上的 `rooms` 统计改成更中性的“会话/任务”表达，避免继续把 room 当主概念暴露。
- 未被引用的旧房间群聊前端页面、入口和 UI 组件可以删除。
- `RoomSettingsDialog`、房间 fallback routing 类型和 API 若仍被资源库、任务或兼容上下文引用，先保留。
- 后端 `rooms/messages/dispatcher` 暂不删除，不删表、不做迁移。

## 测试与验证

后端测试：

- `settingsRepo` 保存、读取、清空 `global_session_prompt`。
- 系统设置 route 接收和返回 `global_session_prompt`，并拒绝超长输入。
- `dispatchSessionUserMessage()` 运行时 prompt 最前面包含 `Global Session Instruction`。
- 未配置时 runtime prompt 不出现注入块。

前端测试：

- 系统设置表单渲染“会话提示词”分类。
- 输入提示词后保存 patch 包含 `global_session_prompt`。
- 空输入保存为清空语义。
- 字符计数和超长状态可见。

最终验证：

- 定向运行相关后端 `node --import tsx --test` 测试。
- 定向运行相关前端 `node --import tsx --test` 测试。
- 运行 `npm run build` 作为 TypeScript 与打包验证。

## 风险与处理

- Prompt 过长会增加每轮 session 成本：通过最大长度和字符计数控制。
- 注入块可能与用户输入冲突：固定放在 `User Request` 前，并明确标题，便于调试和审计。
- 旧 room 概念仍被资源库、workflow、历史来源复用：本轮不删除后端兼容层。
- 当前工作区已有未提交改动：实现时需要只修改本任务相关文件，提交时避免带入无关改动。

## 验收标准

1. 系统设置中可以编辑、保存、清空全局会话提示词。
2. Session Workspace 每次用户消息运行前，ACP runtime prompt 最前面包含该提示词。
3. 未配置时不改变现有 session prompt。
4. 用户消息展示、存储和 `/chat` 全局聊天不受影响。
5. 旧房间群聊不再作为前端主概念暴露，后端兼容层保持可用。
6. 相关定向测试与 `npm run build` 完成并报告结果。

# 会话工作流先分析再展示设计

## 目标

用户发送任务后，中间聊天区必须先展示 planner 的分析正文，再展示任务类型判断和 workflow 流程。workflow 不能在分析前以 planning 卡片抢先出现，也不能吞掉 assistant 的自然语言输出。

## 范围

- 修改 SessionOS workflow intake 的公开阶段语义。
- 修改聊天区 workflow 消息分类规则。
- 保留现有 workflow 卡片、gate、artifact 和 agent assignment 展示。
- 不调整顶部、侧栏、输入框或整体布局样式。

## 设计

初始 workflow run 仍可在后端创建，用于承载 intake 和后续 graph 状态，但公开 `current_stage` 应表示 `analysis`，与内部 `currentNode: context` 和 `activeSuperpowersStage: intake` 一致。启动文案显示“当前阶段：analysis”，避免用户误以为已经跳过分析进入 planning。

前端只把 workflow 控制事件归入 workflow 卡片，例如 `sender_id=workflow`、`event_type=workflow_*`、系统恢复/阶段推进消息。带 `workflow_run_id` 的 assistant `agent_stream` 不再自动归入 workflow 卡片，因为这类消息包含 planner 分析正文、intent JSON 和计划正文，必须作为聊天消息显示。

## 验收

- 用户消息后，初始 workflow intake 消息显示 analysis，不显示 planning。
- planner 的自然语言分析正文作为普通 assistant 聊天消息渲染。
- workflow 系统事件仍合并为一个 workflow 聊天卡片。
- workflow artifacts/gates/controller 仍挂载到最新 workflow 卡片。

## 风险

- 旧测试大量断言 planning，需要只更新与 intake 公开阶段相关的断言。
- assistant JSON intent 也会作为聊天消息显示；本次先保持，因为用户要求展示分析与判断过程，后续可再做正文折叠或摘要优化。

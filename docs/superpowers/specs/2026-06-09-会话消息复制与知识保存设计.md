# 会话消息复制与知识保存设计

## 背景

目标页面是项目会话页：

`/projects/:projectId/sessions/:sessionId`

当前会话 transcript 中已有“保存为知识”入口，但它位于消息动作区，和 Markdown 的“预览 / 源码”切换不够紧密。用户希望把“保存为知识”放到智能体回复消息中，并放在“预览 / 源码”旁边；同时新增一键复制功能。

本次头脑风暴确认采用方案 A：在消息头右侧使用同一组轻量操作按钮。

## 目标

1. 所有会话消息都提供“复制”按钮，包括用户消息、系统消息和智能体回复。
2. 只有智能体回复提供“保存为知识”按钮。
3. “复制 / 保存为知识 / 预览 / 源码”在视觉上属于同一消息头工具组。
4. 复制内容使用消息或运行输出的原始文本，不受当前“预览 / 源码”显示模式影响。
5. 普通智能体消息和运行记录中的智能体输出都能保存为知识。

## 非目标

1. 不改变后端知识库 schema。
2. 不改变知识笔记抽取、去重、切块和索引逻辑。
3. 不为用户消息或系统消息提供“保存为知识”。
4. 不重做 transcript 信息架构、消息排序或 FlexLayout 中间区结构。

## 当前实现依据

相关前端入口：

- `packages/frontend/src/pages/SessionWorkspacePage.tsx`
  - 已有 `saveKnowledgeMutation`
  - 已调用 `api.createSessionKnowledgeNote(sessionId, { messageId })`
- `packages/frontend/src/session-ui/SessionShellView.tsx`
  - `TranscriptCanvas` 构建消息和 run 的时间线
  - `TranscriptMessage` 渲染普通会话消息
  - run 输出通过 `runOutputText(run, agentEvents)` 生成
- `packages/frontend/src/session-ui/SessionMessageBubble.tsx`
  - 渲染消息头、消息体、附件
  - `MarkdownDisplaySwitch` 渲染“预览 / 源码”
- `packages/frontend/src/session-ui/session-os.css`
  - 已有 `.deepsea-message__action` 和 `.deepsea-markdown-switch` 样式

相关 API：

- `CreateSessionKnowledgeNoteInput` 支持 `messageId?: string`、`title?: string`、`content?: string`
- 后端 `createSessionKnowledgeNote` 会在无 `messageId` 时使用 `title + content` 创建 session note

因此 run 输出保存为知识可以走现有接口，不需要后端改造。

## 交互设计

### 普通会话消息

消息头右侧显示统一工具组：

1. `复制`
2. `保存为知识`，仅 assistant 消息显示
3. `预览`
4. `源码`

用户消息和系统消息只显示 `复制`。如果内容不是 Markdown，仍显示 `复制`，但不显示 `预览 / 源码`。

### 运行记录中的智能体输出

run 输出当前使用 `deepsea-run-log` 结构，不经过 `SessionMessageBubble`。为了保持体验一致，run 标题行右侧也显示同一工具组：

1. `复制`
2. `保存为知识`
3. `预览`
4. `源码`

`复制` 和 `保存为知识` 使用 `runOutputText(run, agentEvents)` 作为原始内容。

### 状态反馈

- 复制成功：按钮短暂显示 `已复制`，约 1.2 秒后恢复。
- 复制失败：显示 toast 错误。
- 保存为知识提交中：对应消息或 run 输出按钮显示 `保存中` 并禁用。
- 保存成功：沿用现有 toast，显示“已保存为知识笔记”或“知识笔记已存在”。
- 保存失败：沿用现有错误 toast。

## 数据流设计

### 复制

复制是纯前端行为：

1. 用户点击 `复制`
2. 前端调用 `navigator.clipboard.writeText(content)`
3. 成功后更新局部 copied 状态
4. 失败时 toast 报错

复制内容来源：

- 普通消息：`message.content`
- run 输出：`runOutputText(run, runAgentEvents)`

### 保存为知识

普通 assistant 消息：

1. 点击 `保存为知识`
2. `SessionWorkspacePage` 调用 `api.createSessionKnowledgeNote(sessionId, { messageId })`
3. 后端按消息内容创建或复用 session note

run 输出：

1. 点击 `保存为知识`
2. 前端构造：
   - `title`: `智能体回复 - {agentLabel} - {time}`
   - `content`: `runOutputText(run, runAgentEvents)`
3. `SessionWorkspacePage` 调用 `api.createSessionKnowledgeNote(sessionId, { title, content })`
4. 后端按内容 hash 去重并创建 session note

保存中状态需要能区分 message 和 run，建议使用统一 action key：

- message: `message:{message.id}`
- run: `run:{run.id}`

## 组件设计

新增或调整：

- 将 `onSaveKnowledge` 从只接收 `SessionMessage` 调整为接收统一输入：
  - `{ kind: 'message'; message: SessionMessage }`
  - `{ kind: 'run'; run: SessionRun; title: string; content: string }`

- `TranscriptMessage` 负责普通消息的复制与保存入口
- run 分支负责 run 输出的复制与保存入口

### `SessionMessageBubble.tsx`

新增或调整：

- 支持传入一个消息头工具组，而不是仅传入松散的 `actions`
- 保持 `MarkdownDisplaySwitch` 在工具组末尾
- 复制按钮可以由上层传入，也可以由 `SessionMessageBubble` 内部根据 `content` 创建；实现时优先选择最小改动方案

### `session-os.css`

新增或调整：

- 将 `.deepsea-message__action` 和 `.deepsea-markdown-switch` 合并到同一行视觉节奏
- 窄屏时允许工具组换行，但保持按钮不挤压发送者标签和时间
- 保持 22px 左右的紧凑按钮高度，符合当前 session UI 密度

## 可访问性

- `复制` 按钮需要 `aria-label="复制消息内容"` 或 `aria-label="复制智能体输出"`
- `保存为知识` 按钮需要 `aria-label="保存消息为知识"` 或 `aria-label="保存智能体输出为知识"`
- 复制成功后的文本变化要同步到按钮可见文本，便于屏幕阅读器获得状态变化
- 禁用态按钮保留清晰视觉状态

## 验证方式

实现完成后执行：

1. `npm run build`
2. 相关前端测试，例如 `npm test -w @openclaw-room/frontend -- SessionShell`
3. Playwright smoke：
   - 打开目标会话页
   - 检查 assistant 消息头旁显示 `复制 / 保存为知识 / 预览 / 源码`
   - 检查用户消息、系统消息显示 `复制`，不显示 `保存为知识`
   - 点击复制，确认按钮状态变为 `已复制`

## 风险与约束

- Clipboard API 在非安全上下文或权限受限环境可能失败，需要 toast 明确反馈。
- run 输出没有原始 `messageId`，保存为知识会使用 `title + content`，知识源 metadata 中不会记录 `source_message_id`。
- transcript 目前只显示最近 36 个时间线项；本次不改变该限制。
- 当前工作区已有其他未提交改动，实施时需要继续只触碰本设计相关文件。

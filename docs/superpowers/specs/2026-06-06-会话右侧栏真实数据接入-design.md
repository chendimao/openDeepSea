# 会话右侧栏真实数据接入设计

## 背景

当前 Session Workspace 右侧栏已经具备四个运行态模块：

- 会话计划
- 代理运行
- 工具调用
- 待提交变更

这些模块的 UI 已经接入 `SessionWorkspacePayload`，但数据口径不完整：

- `planItems` 依赖 `session_plan_items`，ACP `plan_update` 事件尚未稳定派生为计划项。
- `runs` 来自真实 `session_runs`，但右侧栏仍存在模型、耗时等兜底展示，容易让用户误解为真实运行。
- `toolRows` 由 `session_evidence_events` 派生，但工具名、目标、状态和 ACP 原始 payload 的映射还不够完整。
- `diffRows` 当前读取工作区 `git status/diff`，会混入非本次会话产生的未提交变更。

本次目标是让右侧栏全部使用 ACP 调用记录产生的真实数据，并把“待提交变更”改为“本次会话变更”。

## 目标

1. 会话计划展示来自本 session ACP `plan_update` 记录的计划项。
2. 代理运行展示当前或最近一次真实 `session_runs` 记录，不显示伪造模型、耗时或默认运行信息。
3. 工具调用展示来自本 session ACP 工具事件的真实调用记录。
4. 本次会话变更只展示本 session ACP 文件变更记录，不读取全工作区未提交状态作为数据源。
5. 首次 snapshot 与 WebSocket 增量更新保持同一数据口径。

## 非目标

- 不引入新的工作流或多智能体调度模型。
- 不把全工作区 git dirty 状态混入“本次会话变更”。
- 不新增复杂 diff viewer，只保留右侧栏列表视图所需摘要。
- 不解决历史旧 session 缺失 ACP 结构化事件的问题；旧数据按已有记录尽力展示。

## 数据来源

唯一可信来源为当前 session 的 ACP 调用记录，落库位置包括：

- `session_runs`
- `session_agent_events`
- `session_evidence_events`

其中：

- `session_runs` 提供代理运行基本信息。
- `session_agent_events.payload_json` 保存 ACP chunk 的 `event`、`trace`、`rawEvent`。
- `session_evidence_events.payload` 保存工具调用、文件变更、计划更新等已标准化的 evidence。

`git status` 仍可用于底部状态栏的工作区风险判断，但不用于右侧栏“本次会话变更”列表。

## 推荐架构

采用后端派生统一视图方案。

在 `packages/backend/src/session-workspace-view-model.ts` 内集中维护 Session Inspector 派生逻辑：

- `buildSessionToolRows(evidence)`：从 evidence 派生工具调用行。
- `buildSessionDiffRowsFromAcp(evidence, agentEvents)`：从 ACP 文件变更记录派生本次会话变更。
- `upsertSessionPlanItemsFromAcp(sessionId, evidence, agentEvents)` 或等价同步函数：从 `plan_update` 事件派生 `session_plan_items`。

`packages/backend/src/session.routes.ts` 的 `buildWorkspacePayload` 只负责调用派生函数，不直接拼接复杂业务规则。

`packages/frontend/src/session-ui/SessionShellView.tsx` 只负责展示 payload，不解析 ACP 原始事件。

## 派生规则

### 会话计划

识别 ACP `plan_update` 事件：

- `session_agent_events.payload_json.event.type === "plan_update"`
- 或 `session_evidence_events.payload.event.type === "plan_update"`
- 或 payload 中存在 `entries` 数组且事件类型表示计划更新

每个 entry 映射为 `SessionPlanItem`：

- `title`：优先取 `title`，否则取 `content`、`text`、`description` 中第一个非空字符串。
- `status`：映射到 `pending`、`in_progress`、`completed`、`blocked`、`failed`、`skipped`。
- `priority`：按 entry 顺序递增。
- `source`：记录为 `acp_plan_update`。
- `evidence_event_id`：若来源为 evidence，则关联对应 event id。

同一次 ACP 计划更新以最新完整计划为准；如果 provider 只发增量，则按稳定 key 合并。稳定 key 优先级：

1. entry 自带 `id`
2. `title`
3. 顺序号

### 代理运行

继续使用 `session_runs`。

右侧栏展示策略：

- 优先展示 active run：`queued`、`running`、`retrying`、`paused`。
- 没有 active run 时展示最近一次 run。
- 没有任何 run 时显示空状态。
- 不再展示 `gpt-test`、`02:14:05` 这类假兜底值。

### 工具调用

从本 session evidence 派生：

- `tool_call`
- `tool_result`
- `file_read`
- `file_diff`
- `test`
- `build`
- `browser_check`

字段映射：

- `action`：按事件类型和工具名映射为 `read`、`write`、`edit`、`exec`、`browser`、`tool`。
- `label`：优先使用 ACP 工具名或标题，例如 `apply_patch`、`exec_command`、`open`。
- `target`：优先取文件路径、命令、URL、工具 input 摘要，再退回 title/summary。
- `status`：优先使用 ACP event status；错误 severity 映射为 `failed`。
- `durationMs`：有 duration 才展示，无则保持 `null`。

### 本次会话变更

替换右侧栏“待提交变更”：

- 标题改为“本次会话变更”。
- 英文辅助文案改为 `Session Changes`。
- 统计文案改为“本会话 N 个文件变更”或“本会话暂无文件变更”。

只从当前 session ACP 记录派生文件列表：

- `file_diff` evidence payload 的 `path`、`file`、`patch`、`additions`、`deletions`。
- 工具调用中识别出的编辑类工具，例如 `apply_patch`，且 payload 能解析到文件路径。

同一文件多次变更合并为一行：

- `path` 相同则聚合 additions/deletions。
- `status` 取最后一次可识别状态。
- `summary` 记录最近一次工具名或 diff 摘要。

不展示未被 ACP 记录命中的 git dirty 文件。

## 实时更新

当前 `session_evidence:new` 增量只追加 `payload.evidence` 和 `activeSession.evidence`，不会同步刷新 `toolRows` 和 `diffRows`。

实现时新增后端派生快照事件，例如 `session_inspector:snapshot`：

- 后端在新增 plan/tool/diff 相关 evidence 后，重新计算当前 session 的 `planItems`、`toolRows`、`diffRows`。
- 广播事件携带完整派生结果，而不是只携带单条增量。
- 前端 reducer 收到事件后替换 `activeSession.planItems`、`toolRows`、`diffRows`。
- 前端不解析 ACP 原始 payload，避免 snapshot 与增量口径分叉。

如果新增 evidence 不影响右侧栏，后端可以不广播该快照事件。

## 前端展示调整

`SessionShellView.tsx` 中：

- `RunModule` 无 run 时显示“暂无代理运行”。
- `DiffModule` 重命名为面向“本次会话变更”的展示组件或至少更新文案。
- 删除“存在未应用的 Compact 预览，Fork 可能丢失上下文”这类与本模块不直接相关的固定提示，避免静态 mock 感。
- 保持现有布局，不做大范围视觉重构。

## 测试策略

后端：

- 覆盖 ACP `plan_update` 到 `session_plan_items` 的派生。
- 覆盖 `tool_call/tool_result/file_diff` 到 `toolRows` 的派生。
- 覆盖 `file_diff/apply_patch` 到“本次会话变更”的聚合。
- 覆盖 git dirty 文件不会出现在 `diffRows`。

前端：

- 覆盖标题和文案从“待提交变更/Uncommitted”改为“本次会话变更/Session Changes”。
- 覆盖无 run 时不显示假模型和假耗时。
- 覆盖 `session_evidence:new` 后右侧栏派生数据更新或 snapshot 刷新行为。

整体：

- 最低验证运行 `npm run build`。
- 若实现触及单测覆盖范围，运行相关 package 测试。

## 风险与约束

- 不同 ACP provider 的 raw payload 字段差异较大，派生 helper 必须容忍缺字段。
- 旧 session 可能没有结构化 `plan_update` 或 `file_diff`，需要显示空状态而不是伪造内容。
- 如果 provider 只输出文本 diff，文件路径可能无法可靠恢复；此时应记录工具调用，但不生成本次会话变更行。
- 后端广播协议改动需要同步更新前端 WS 类型和 reducer 测试。

## 验收标准

1. 打开目标 session 页面时，右侧栏四个模块均来自真实 payload。
2. “本次会话变更”只包含当前 session ACP 记录命中的文件变更。
3. 工作区中非本 session 的未提交文件不会出现在右侧栏变更列表。
4. ACP 运行过程中新增 plan/tool/diff 事件后，右侧栏能随 snapshot 或增量事件更新。
5. 没有真实运行或变更时，界面显示空状态，不显示 mock 值。

# Planner 读写提交权限设计

## 背景

当前会话 planner 的 runtime 由 `resolveSessionPlannerRuntime()` 解析，实际读取全局内置 `planner` agent 的默认 ACP runtime profile。旧版本内置 planner 使用 `read-only`，只能读文件，不能写入项目、运行需要写权限的闭环动作，也不能表达提交能力。

用户确认需要升级到更激进的第 3 种方案：planner 需要具备项目根目录读写权限，并允许完整闭环中的 `commit` 工具。

## 目标

- 内置 `planner` 默认以 `workspace-write` ACP 权限运行。
- 内置 `planner` 的 tool policy 包含 `read_files`、`write_files`、`run_shell`、`commit`。
- 内置 `planner` 的 workspace policy 为读取项目根目录、写入项目根目录。
- 旧数据库中仍处于默认只读边界的内置 `planner` 自动升级。
- `restoreBuiltInDefaults()` 恢复 `planner` 时恢复到新的读写提交边界。
- session planner runtime snapshot 能反映新的权限和工具边界。

## 非目标

- 不把其他只读专家角色改成可写。
- 不调整 ACP provider 的 CLI 参数映射；现有 adapter 已能通过 `workspace-write` 启动可写沙箱。
- 不改变项目级 `session_planner_acp_backend` 覆盖逻辑。
- 不处理用户主动自定义过的 planner runtime profile，除非它仍完全匹配旧版默认只读边界。

## 设计

### 模板默认值

`packages/backend/src/agent-templates.ts` 中的内置 `planner` 使用新的 runtime boundary：

```ts
{
  acp_permission_mode: 'workspace-write',
  tool_policy: { allowed: ['read_files', 'write_files', 'run_shell', 'commit'] },
  workspace_policy: { read: ['.'], write: ['.'] },
  memory_scope: 'agent',
}
```

这让新安装、新恢复默认值和后续模板读取都统一为可读写提交。

### 旧数据升级

`packages/backend/src/repos/agents.ts` 保留内置 agent runtime profile version 机制。对 `builtin_key === 'planner'` 且仍完全匹配旧版默认只读边界的记录，在 `agentRepo.ensureBuiltInAgents()` 中刷新为新模板边界。

旧版默认只读边界定义为：

- `default_acp_permission_mode === 'read-only'`
- `default_runtime_backend === 'acp'`
- `default_memory_scope === 'room'`
- `default_tool_policy.allowed === ['read_files']`
- `default_workspace_policy.read === ['.']`
- `default_workspace_policy.write === []`

这样能自动修复历史默认数据，同时避免覆盖用户已经主动改过的非默认配置。

### Session Planner Runtime

`resolveSessionPlannerRuntime(projectId)` 继续只负责读取全局内置 planner 和项目级 backend override。权限、tool policy、workspace policy、memory scope 都来自全局 planner runtime profile。

因此只要模板和旧数据升级正确，session planner 会自然获得：

- `permissionMode: 'workspace-write'`
- `toolPolicy.allowed` 包含 `commit`
- `workspacePolicy.write` 包含 `.`
- runtime snapshot 写入同样信息

### 测试覆盖

需要同步以下测试：

- `packages/backend/src/agent-templates.test.ts`
  - planner 模板断言改为 `workspace-write`
  - tool policy 断言包含 `commit`
  - workspace policy 断言写入 `.`
  - memory scope 断言为 `agent`
- `packages/backend/src/repos/agents.test.ts`
  - 内置 agent seed 默认边界断言改为 planner 可写提交
  - 增加旧只读 planner 自动迁移用例
  - restore defaults 继续通过模板恢复新边界
- `packages/backend/src/session-planner-runtime.test.ts`
  - session planner runtime 断言 `workspace-write`
  - 断言 write policy 包含 `.`
  - 断言 tool policy 包含 `commit`

## 风险与约束

- `planner` 获得写入和提交能力后，普通会话 planner 也能执行代码修改和提交；这是用户明确选择的行为。
- ACP provider 的真实提交能力仍依赖运行时 CLI、Git 状态和用户当前仓库权限。
- 当前工作区已有多处未提交改动，实施和提交时必须只纳入本任务相关文件，不能覆盖或回滚无关改动。

## 验证方式

定向验证：

```bash
npm test -- --runInBand packages/backend/src/agent-templates.test.ts packages/backend/src/repos/agents.test.ts packages/backend/src/session-planner-runtime.test.ts packages/backend/src/session-runtime.test.ts
```

如果仓库未配置该测试命令或测试 runner 参数不兼容，则改用项目现有 Node test 命令运行这些文件，并记录实际命令与结果。

最低完成验证：

```bash
npm run build
```

## 验收标准

- 新建或恢复默认的内置 `planner` 为 `workspace-write`。
- 历史默认只读 `planner` 会在 seed 时升级为读写提交边界。
- session planner runtime 解析出的权限和 snapshot 与新边界一致。
- 相关定向测试和 `npm run build` 有新鲜验证结果。

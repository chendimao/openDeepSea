# Workflow 消息流转指挥中枢化设计

## 背景

当前会话中间区的 workflow 展示由多个独立模块组成：

- `WorkflowArtifactGatePanel` 展示 spec / plan 等产物确认。
- `WorkflowControllerPanel` 展示 controller、stage、next action。
- `WorkflowAgentAssignmentTable` 展示子代理分派。
- 每条 agent run 内部由 `SessionRunTimeline` 混排正文、事件行和详情按钮。

这些信息本身有价值，但默认展示层级过多，容易在正式 workflow 中形成“状态卡、分派表、正文、工具事件、metadata”并列堆叠，阅读重心不清晰。

本次设计目标是参考“深海指挥中心 - 多智能体协作动态流版 (4:3)”中间聊天区域的任务消息 workflow 流转感，将 workflow 展示改为更明确的“指挥中枢流”。

## 范围

本设计覆盖会话中间聊天区两层 UI：

1. 顶部 workflow 总览区：替代当前分散的 Gate / Controller / Assignments 三块默认展示。
2. 每条 agent run 消息内部：替代当前正文与事件混排的 run timeline 默认样式。

不在本次范围内：

- 后端 workflow 状态机和调度逻辑。
- workflow artifact、gate、assignment 的数据结构变更。
- 右侧 inspector 的 workflow 模块重构。
- 消息发送、审批、重试、复制、保存知识等已有行为改动。

## 设计方向

采用方案 C：指挥中枢流。

核心原则：

- 默认展示推进 workflow 所需的关键信息，隐藏噪声级事件。
- 将“任务态势”和“单次智能体执行”分层，不再在同一视觉层级里混排。
- 保留正文阅读的主通道，工具调用和事件详情通过折叠或弹窗按需查看。
- 视觉上延续深海指挥中心风格：深色背景、细线框、状态色、紧凑高信息密度，但避免装饰压过内容。

## 顶部总览：Workflow Mission Strip

将当前顶部的 `WorkflowArtifactGatePanel`、`WorkflowControllerPanel`、`WorkflowAgentAssignmentTable` 合并为一个默认可见的 Mission Strip。

### 信息结构

Mission Strip 包含四个区域：

1. 任务身份区
   - workflow / task 标题。
   - 当前 intent、controller、next action。
   - blocker 存在时显示为警告行。

2. 阶段轨道
   - 固定展示 `analysis`、`planning`、`assignment`、`implementation`、`code_review`、`acceptance`。
   - 每个阶段显示状态：done、active、gate、blocked、failed、pending。
   - 当前阶段高亮，已完成阶段收敛为低噪声成功态。

3. 门禁摘要
   - 显示 pending gate 数量。
   - 有 pending artifact 时提供确认入口。
   - artifact 正文默认不直接完全展开，避免压住聊天流。

4. 子代理摘要
   - 显示参与 agent 数量和核心 role。
   - 默认展示 agent / role / execution mode / scopeWrite 摘要。
   - scope 过长时折叠，完整内容进入详情。

### 行为

- 无 workflow 数据时不渲染。
- 有 pending gate 时，Mission Strip 置顶于 transcript scroll 内，并保持明确 CTA。
- artifact 仍支持“确认”和“请求 planner 修改”。
- 详细 artifact 内容可通过展开区或弹窗查看，不作为默认长卡片堆在顶部。

## 单条执行：Run Flow Capsule

每条 agent run 改为 Run Flow Capsule。它仍然是 transcript timeline 中的一条 assistant run，但内部层级重排。

### 信息结构

Run Flow Capsule 包含三层：

1. 状态头
   - agent 名称和角色。
   - workflow stage。
   - run status、耗时、事件数量。
   - 现有操作按钮：复制、保存为知识、打开设计预览、预览/源码切换。

2. 关键事件轴
   - 默认只显示关键事件类别，例如 context、tool、edit、verify、error、done。
   - 同类低价值事件合并计数。
   - 当前 streaming 事件用 active 状态标识。
   - 点击“查看事件详情”打开已有事件详情弹窗或新的详情面板。

3. 正文阅读区
   - 保留当前 `MessageContent` / markdown preview 能力。
   - streaming cursor、workspace file ref、代码块和图片证据继续工作。
   - 正文区域不被事件行打断，事件只作为左侧或顶部辅助轨道存在。

### 事件折叠规则

默认展示：

- 起始上下文读取。
- 关键工具调用或批量工具调用摘要。
- 文件修改、验证、错误、完成类事件。
- 与 workflow stage 变化、gate、assignment 相关的事件。

默认隐藏到详情：

- 高频 token / trace / stdout 片段。
- 重复的同类型事件。
- payload JSON。
- 对用户理解推进状态没有帮助的内部 metadata。

## 组件边界

优先保持实现局部化：

- 在 `SessionShellView.tsx` 中新增或改造 mission strip 与 run capsule 的组合组件。
- 在 `SessionRunTimeline` 附近提取事件归类函数，避免 JSX 内堆复杂判断。
- 在 `session-os.css` 中新增 `deepsea-workflow-mission-*` 与 `deepsea-run-capsule-*` 样式。
- 保留 `SessionMessageBubble` 的普通消息职责，不把 workflow 专属布局塞进普通消息气泡。

建议组件：

- `WorkflowMissionStrip`
- `WorkflowStageRail`
- `WorkflowGateSummary`
- `WorkflowAgentRoster`
- `RunFlowCapsule`
- `RunEventRail`

## 数据映射

现有数据足够支撑第一版，不需要后端改动。

- `detail.workflowArtifacts` 和 `detail.workflowGates` 生成门禁摘要。
- `detail.workflowController` 生成任务身份、当前阶段和 next action。
- `detail.workflowAgentAssignments` 生成 agent roster。
- `SessionRun.workflow_stage`、run status、timestamps 生成 run 状态头。
- `detail.agentEvents` 生成关键事件轴。
- run stdout / stderr / activity log 继续作为正文 fallback。

若某些字段为空，UI 应降级：

- 无 controller 时不显示 Mission Strip。
- 无 assignment 时隐藏 agent roster。
- 无 agent events 时 Run Flow Capsule 只显示状态头与正文。
- 无 workflow stage 时显示 `general` 或隐藏阶段标签。

## 视觉与交互要求

- 中间区保持高密度但不拥挤，卡片半径不超过现有设计习惯。
- 状态色语义稳定：success、active、warn、danger、muted。
- 所有按钮保留可访问名称。
- 长标题、长 scope、长 agent 名必须截断并提供 `title`。
- 移动端或窄容器下阶段轨道允许横向滚动或换为紧凑两行。
- 不引入新的重型动效；仅允许轻量 active pulse 或 streaming 状态提示。

## 测试与验证

实施后至少验证：

- `npm run build`
- 相关 React render 测试，覆盖：
  - pending gate 的 Mission Strip。
  - 无 workflow 数据时不渲染 Mission Strip。
  - 有 agent events 的 Run Flow Capsule。
  - 无 agent events 时正文正常显示。
  - 复制、保存知识、预览/源码切换入口仍存在。
- Playwright 或截图 smoke：
  - 桌面 1280x1024 中间聊天区不重叠。
  - 移动 390x844 下阶段轨道和 run capsule 不溢出。

## 风险

- `SessionShellView.tsx` 已经较大，新增逻辑要避免继续堆在单个函数里。
- workflow artifact 内容可能很长，必须从默认展开改为摘要优先，否则顶部仍会压住聊天。
- agent events 类型可能不稳定，事件归类函数需要保守兜底。
- 当前工作区存在未提交改动，实施时要避免混入无关文件。

## 验收标准

- 中间聊天区 workflow 默认展示从分散堆叠变为一个清晰 Mission Strip。
- 每条 agent run 内部从正文/事件混排变为 Run Flow Capsule。
- 用户能一眼看出当前阶段、门禁、下一步、参与 agent 和单条 run 的执行进度。
- 原有核心操作不丢失。
- 构建通过，关键 UI 无明显重叠或文字溢出。

# 会话侧栏筛选排序与新增项目设计

## 背景

会话页面左侧已经有项目会话树、会话置顶、项目拖拽排序、项目菜单和新建会话入口。当前标题行右侧已有两个图标按钮位置，但整理按钮尚未提供筛选与排序交互，新增项目按钮也未接入现有 `CreateProjectDialog`。

本设计基于参考图，完善左侧项目列表的整理菜单、新增项目入口、按项目与时间顺序两种浏览方式，并降低左上角“项目”标题的字号层级。

## 目标

1. 在会话页面左侧项目栏增加一个整理菜单，支持切换整理模式、排序条件和显示范围。
2. 在同一标题行增加新增项目按钮，并打开现有新增项目弹窗。
3. 支持按项目树浏览和时间顺序会话列表浏览。
4. 时间顺序列表按照最新使用的会话排序，最新使用时间优先使用 `last_viewed_at`，缺失时回退 `updated_at`。
5. 排序条件同时影响按项目模式和时间顺序模式。
6. 显示范围默认是所有聊天，也可以切换到只看置顶会话。
7. 保持现有左栏密度和视觉风格，不引入全新的侧栏框架。

## 非目标

1. 不改归档、历史记录或关闭会话的数据模型。
2. 不把 history records 混入本次左侧时间顺序列表。
3. 不重做全局导航、顶部栏、右侧检查器或中间会话正文区域。
4. 不改变项目删除、项目重命名、会话置顶和新建会话的既有行为。

## 已确认决策

### 整理菜单方案

采用单一弹出菜单方案。标题行右侧保留两个按钮：

- 整理按钮：打开 Radix `DropdownMenu`，包含三组菜单项。
- 新增项目按钮：打开现有 `CreateProjectDialog`。

菜单分组：

- 整理：`按项目`、`时间顺序列表`
- 排序条件：`已创建`、`已更新`
- 显示：`所有聊天`、`置顶`

默认状态：

```text
按项目 + 已更新 + 所有聊天
```

### 置顶筛选语义

`置顶` 只筛选会话置顶状态，也就是：

```ts
session.pinned_at !== null
```

项目置顶不参与本次显示范围筛选。

### 排序作用范围

排序条件同时作用于两种整理模式：

- 按项目模式：重排项目，也重排项目内会话。
- 时间顺序列表：重排平铺会话列表。

## 交互设计

### 按项目模式

按项目模式保留现有项目树：

- 顶部仍是“新建会话”和搜索输入框。
- 标题显示为 `项目`，字号从当前大标题降到更轻的小标题层级。
- 项目行继续展示文件夹图标、项目名和悬浮操作按钮。
- 会话行继续展示标题、相对时间和置顶按钮。
- 筛选或搜索后，如果某项目没有可见会话，则隐藏该项目，减少空树占位。

### 时间顺序列表模式

时间顺序列表不展示项目树，改为全局会话平铺列表：

- 标题显示可改为 `聊天`，用于提示当前不是项目树。
- 每行展示会话标题、所属项目名和相对时间。
- 点击会话仍调用 `onOpenSession(projectId, sessionId)`。
- 会话置顶按钮仍可保留在行首或悬浮区域，行为与按项目模式一致。
- 当前会话需要有明确高亮状态。

### 整理菜单反馈

菜单项右侧使用勾选标记表示当前状态。每组互斥选择只允许一个值生效。

菜单更新后即时重算左侧列表，不需要额外确认按钮。

## 数据规则

### 状态模型

`ProjectSessionTreeRail` 增加三个本地状态：

```ts
type SessionSidebarGroupMode = 'project' | 'time';
type SessionSidebarSortMode = 'created' | 'updated';
type SessionSidebarVisibility = 'all' | 'pinned';
```

建议状态键：

```text
opendeepsea.sessionSidebar.viewPrefs
```

持久化内容：

```ts
{
  groupMode: 'project',
  sortMode: 'updated',
  visibility: 'all',
}
```

读取失败或值不合法时回退默认值。

### 会话可见性

基础集合使用当前会话侧栏可见的活跃会话集合：

- 排除 `status === 'archived'` 的会话。
- 排除已关闭或已归档的会话，沿用后端 `activeSessions` 的语义。
- 当前会话如果不在 `activeSessions` 中，沿用现有 fallback，把当前会话补入列表。

显示范围：

- `all`：显示基础集合。
- `pinned`：只显示 `pinned_at !== null` 的会话。

### 会话排序

`updated` 排序：

```ts
const lastUsedAt = session.last_viewed_at ?? session.updated_at;
```

按 `lastUsedAt` 降序排列。

`created` 排序：

按 `session.created_at` 降序排列。

为了支持此规则，需要把 `created_at` 和 `last_viewed_at` 补进 `ActiveSessionSummary` 的前后端类型、后端 `buildActiveSessionSummary`、前端 `projectSessionToActiveSummary` 和相关 websocket payload 处理。

### 项目排序

按项目模式下，项目排序也跟随 `sortMode`：

- `created`：按 `project.created_at` 降序。
- `updated`：按 `project.updated_at` 降序。

为了支持项目 `updated` 排序，需要把 `updated_at` 补进 `SessionProjectSwitcher.projects` 的前后端类型和 `buildSessionProjectSwitcher` 返回值。

项目置顶和手动拖拽排序的既有语义仍保留在数据层，但本次视图排序选择优先表达用户当前菜单选择。手动拖拽排序仍可在按项目模式使用；当用户选择创建或更新排序时，拖拽结果不会覆盖当前排序视图。

## 组件与数据流

### `SessionWorkspacePage.tsx`

新增 `createProjectOpen` 状态：

```ts
const [createProjectOpen, setCreateProjectOpen] = useState(false);
```

向 `SessionShell` 传入：

```ts
onCreateProject={() => setCreateProjectOpen(true)}
```

在页面根部渲染：

```tsx
<CreateProjectDialog open={createProjectOpen} onOpenChange={setCreateProjectOpen} />
```

创建成功后沿用 `CreateProjectDialog` 现有 `queryClient.invalidateQueries({ queryKey: ['projects'] })`。如需要同步 websocket workspace snapshot，可在后续实现中观察现有 query 和 socket 刷新是否足够。

### `SessionShell.tsx`

新增可选 prop：

```ts
onCreateProject?: () => void;
```

透传给 `SessionShellView`。

### `SessionShellView.tsx`

`ProjectSessionTreeRail` 负责：

- 管理整理菜单三段状态。
- 从 `projects`、`sessions`、`currentSession` 构建按项目树数据。
- 从同一基础集合构建时间顺序列表数据。
- 根据搜索词、显示范围和排序条件计算最终可见列表。
- 调用 `onCreateProject` 打开新增项目弹窗。

建议拆出纯函数并覆盖单元测试：

```ts
buildVisibleSessionSidebarModel(input)
buildTimeOrderedSessionRows(input)
sortSessionsForSidebar(sessions, sortMode)
sortProjectsForSidebar(projects, sortMode)
```

函数命名可按现有 `buildProjectSessionTree` 风格调整。

## 空状态

不同空状态使用不同文案：

- 搜索或筛选后没有任何结果：`没有匹配的会话。`
- `置顶` 显示范围下没有置顶会话：`暂无置顶会话。`
- 按项目模式中某个项目没有可见会话：隐藏该项目，不单独显示项目级空状态。

## 可访问性与视觉约束

1. 整理按钮和新增项目按钮必须有明确 `aria-label`。
2. 菜单项使用 Radix DropdownMenu 语义，当前项通过勾选图标和文本状态共同表达。
3. 图标按钮保持 20 到 22px 的稳定点击区域，避免标题行高度跳动。
4. 标题 `项目` 字号降到约 13px，颜色保持弱化，避免抢占会话内容层级。
5. 菜单使用 portal 渲染，避免被左栏滚动容器裁切。

## 测试与验证

### 单元测试

覆盖：

1. 默认状态是 `按项目 + 已更新 + 所有聊天`。
2. `updated` 会话排序使用 `last_viewed_at ?? updated_at`。
3. `created` 会话排序使用 `created_at`。
4. `置顶` 只筛选 `session.pinned_at !== null`。
5. 时间顺序列表不渲染项目树，只渲染会话行和项目名。
6. 按项目模式会按 `sortMode` 排项目和项目内会话。
7. 新增项目按钮从 `SessionShellView` 透传到 `SessionWorkspacePage`。
8. 本地存储值非法时回退默认值。

### 构建验证

运行：

```bash
npm run build
```

### 浏览器验证

使用 Playwright 打开会话页，验证：

1. 整理菜单能打开并展示三组菜单。
2. 切换到时间顺序列表后项目树消失，会话按最新使用时间排序。
3. 切换到置顶后只显示置顶会话。
4. 新增项目按钮能打开 `CreateProjectDialog`。
5. `项目` 标题字号变小，按钮和列表无重叠。

## 风险与边界

1. `ActiveSessionSummary` 类型补字段会影响前后端测试 fixture，需要同步更新测试样例。
2. 若当前 websocket 只推送 `updated_at`，需要确保 `last_viewed_at` 变化也能进入 active session snapshot 或至少在页面刷新后准确。
3. 视图排序和手动拖拽排序存在语义差异。当前设计让菜单排序优先生效，拖拽排序保持为项目数据能力，不作为当前视图排序的强制覆盖。
4. 时间顺序列表依赖跨项目 `activeSessions`，不会包含关闭或归档会话。若后续需要“历史聊天”视图，应另起设计扩展。

## 验收标准

1. 会话页面左侧标题行有整理按钮和新增项目按钮。
2. 整理菜单包含 `整理`、`排序条件`、`显示` 三组，并能即时切换。
3. 默认展示按项目树、已更新、所有聊天。
4. 时间顺序列表按 `last_viewed_at ?? updated_at` 降序展示会话，不展示项目树。
5. 置顶筛选只展示置顶会话。
6. 新增项目按钮打开现有新增项目弹窗。
7. `npm run build` 通过。
8. 浏览器 smoke 验证无明显布局重叠或文字溢出。

# 会话入口状态保留设计

## 目标

用户从会话工作区切换到其他页面后，再点击顶部“会话”入口，应回到之前选中的具体会话，而不是回到 `/` 后重新选择默认会话。

## 当前根因

`SessionWorkspaceKeepAliveHost` 已经把会话页保活，但顶部导航里的“会话”链接固定是 `/`。当用户从 `/projects/:projectId/sessions/:sessionId` 离开后再点“会话”，路由会进入 `/`，前端随后按空 `projectId/sessionId` 请求默认工作区，导致之前选中的会话被覆盖。

## 方案

新增一个轻量的会话路由记忆模块：

- 在命中具体会话路由 `/projects/:projectId/sessions/:sessionId` 时记录最后会话路径。
- `AppShell` 订阅这份记忆，把顶部“会话”入口动态指向最后会话路径。
- 没有记忆或记忆无效时，仍回退到 `/`，保持首次进入行为不变。

## 边界

- 不改后端会话选择规则。
- 不改变当前 keep-alive host 的隐藏/显示策略。
- 不新增全局状态库。
- 仅记录 project/session 路由，不记录会话页内部滚动、输入框草稿或弹窗状态。

## 验证

- 增加前端单元测试，覆盖“已有最后会话时 AppShell 的会话链接指向具体 session”。
- 增加路由记忆 helper 测试，覆盖构造路径、无 session fallback、localStorage 读取容错。
- 运行相关 `node --import tsx --test` 定向测试。
- 运行 `npm run build` 作为最终 TypeScript 与打包验证。
